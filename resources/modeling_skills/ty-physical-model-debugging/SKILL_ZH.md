# 物理模型调试

已有 Modelica 物理模型的具体检查、翻译、初始化、数值运行、生成求解器或 external function 故障直接触发。普通建模、领域设计和纯 API 查询不触发。物理修改/交付前读取 `ty-sysplorer-modeling-rules` 的适用约束；纯日志诊断不启动全部建模工作流。

## 诊断与修复顺序

1. 只读取相关源码和 SHA-256、用户验收约束；不扫描无关 Git、目录和大型生成文件。简单单故障尽量控制调用成本，约 12 次调用仅为参考，不跳过必要验证。
2. 根据模式只诊断或修复。按 check、translate、initialize/simulate 复现到首个失败阶段；已有有效基线直接复用。基线在声明阶段前因环境失败时不修改可疑静态代码，报告 `verification_required`。
3. 检查故障只复验 check；翻译故障在 check 通过后复验翻译。初始化关注合法初值、工作点、状态与导数关系、非线性变量及残差；运行故障记录首错时间、变量/系统、邻近事件及最小覆盖窗口。
4. 修复时提出一个可证伪假设，做最小可逆修改，读回后验证对应阶段及约定终端链。初值、nominal、状态偏好和参数修正必须有直接证据；不要擅自改变物理/控制算法或用数值设置掩盖模型缺陷。
5. 外部 C 关联声明、资源、签名及首条编译/链接/运行证据；边界修复覆盖由声明、初始化、事件和用户条件确定的可达输入域，不只修一个样本。

## 证据与副本

记录源身份与工作身份，不假定会话 CopyModel 保留原 FQN。磁盘隔离且不覆盖未保存 GUI 状态时才可保留 FQN；改名副本须验证包、引用、资源和设置。修改前读 `references/current-mcp-recipes.md`，每次写入保留旧值、检查点及可执行逆操作。

错误 FAQ 按 `references/help-doc-index.md` 和 `scripts/query_sysplorer_help.py` 精确匹配编号/类别与上下文，不把进程退出码当模型错误号。公开库语义使用 `get_lib_model_document`。检查/翻译优先采用对应包装器证据，运行输出截断最多追加一次可归属同一调用的有界读取。

初始化与运行深层问题按需读 `references/initialization-and-runtime.md`。先合法初值/工作点，再状态和导数关系、非线性尺度与残差、明显非法参数，最后仅做一次机制明确的算法/事件/步长敏感性比较，最终恢复原设置验证。高频日志只在必要时启用。

轻量证据不足时说明锚点和字节预算，再读 `references/deep-debugging.md`，用 `scripts/extract_debug_evidence.py` 依次查询 Variables.xml、RMF、Flat、RuntimeDebug C 的必要片段。只允许授权范围内用户自有证据，不从生成文件恢复商业受保护实现；常规有界只读查询不单独审批。

## 任务模式与共用边界

- 入口独立触发，不要求先经过建模主入口或调试总入口。明确领域时直接使用专业调试 Skill。
- 根据请求区分 `diagnose_only` 与 `repair`。只解释/定位问题不授权补丁；仅在请求允许时复现，明确离线审查不执行模型。证据不足如实报告，不将假设称为已解决。
- 记录用户要求的终端阶段及验收条件，复用可归属当前模型和设置的基线、会话、工作副本与检查点。引用其他 Skill 的约束后返回当前步骤，不再次分流、重规划或重复复现。新建过程中的故障处理完后继续原建模任务。
- 离线模型/日志读取不调用会话工具。首次实时访问经 Sysplorer MCP 确认目标，支持时先 `probe` 再 `health`；同一有效会话可复用，切换、断连或基础设施异常后重查。所有 ModelingPy 调用只经 MCP，本地辅助脚本只处理文件。
- 当前已知 API 契约直接复用；未知名称、参数和返回类型在调用前定向确认，文档为空按准确名称查询 Help/签名或对应工具箱文档。不得猜测写入、在目标模型试探未知写接口或全量枚举 API。
- 保护原模型、原 C 源码和未保存 GUI 状态，修复只写已核验的任务自有副本。不用 `extends Original` 冒充副本，不修改生成代码或受保护商业库源码，不以删除断言或扫求解参数掩盖缺陷。
- 现有明确授权继续有效；新增实质性设计或范围变化才请求用户判断。同一假设两轮无改善后停止该策略，转入有用的定向证据或最小案例；相同基础设施操作失败两次后停止重复重试，报告缺口，不为凑次数继续猜测。

## 按范围验收与报告

详细状态见 `references/report-contract.md`。只诊断有充分证据时用 `diagnosis_complete`，说明根因已确认还是仍为假设，不宣称修复。证据不足用 `verification_required`。

修复必须有补丁读回、所需静态及终端阶段通过、原件保护和临时设置恢复。静态/链接验收不自动要求仿真或 stopTime；运行验收达到约定原终点；只有用户要求或异常结果所必需时才读取结果和核验 KPI，否则标记 `not_required`。实际变更图形对象仍完成对应建模交付检查。范围内验证通过用 `verified_solved`；有可重复改善但未完成用 `partially_improved`；必要证据缺失用 `verification_required`；无可继续的授权/能力路径用 `automatic_debugging_stopped`。
