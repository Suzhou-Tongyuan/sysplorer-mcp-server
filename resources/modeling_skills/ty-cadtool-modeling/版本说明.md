# 版本说明

## v1.3.0 (2026-06-15)

依据官方帮助文档（`CADToolBox/Doc` 共 31 篇：流程介绍 / 新手入门 曲柄滑块·牛顿摆·简单油箱 / 应用案例 PickAndPlace·Bulldozer·RobotGrabBall·CATIA双滑块·SolidWorks机械臂·带肋板油箱 / 各元素 how-to）系统提炼**普适建模流程**，重写 skill 使"流程清晰、可对照文档与界面"。逐篇结构化抽取与差距分析见配套研究工作区 `ty-cadtool-modeling-workspace`（含 `doc-digest.md`、`universal-process-and-gaps.md`；置于本 skill 同级目录，仅供留档、不随 skill 分发）。

- **流程重构为官方"五个命名阶段"**。多体：导入→分组→连接和驱动→生成→仿真；流体：导入(切流体台)→切片→端口/介质/重力→生成→仿真。`SKILL.md`/`SKILL_ZH.md` 与两个 workflow 全部按此重排，并新增**「官方术语 ↔ 菜单路径 ↔ MCP/API」映射表**，使盲操作 agent 能用用户/文档的中文词汇推理（每阶段=用 API 复刻对应 UI 步骤）。
- **修正 `PlanarLoopConstraint` 语义（重要）**。经源码核对（`CADToolbox.py:2952` 平面环处理工具）与文档（`HowToUseCADToolBox/PlanarLoopConstraints`）确认：它是**姿态统一**（基准副 + 待调整副 + Z 轴反向 + 基准姿态），用于 CAD 装配精度(~1e-6)<求解精度(1e-10) 导致的**平面环仿真初始化失败**，**不是切割**，且在生成前执行（双滑块案例）。旧文档误标为"生成前切割一个副"，本版在 `api-reference.md`/`multibody-elements.md`/`common-errors.md`/`SKILL*.md`/`使用说明.md` 全部更正；闭环切割另述（分组干净时生成自动切割，兜底 `RevolutePlanarCut`，无独立切割 API）。
- **补齐官方关键事实**：① 闪电模式 + 特征拾取智能推理（拾取圆边/圆柱面→吸附圆心/对齐轴线）——明确"测量即盲态复刻智能推理"（`joint-placement.md`）；② 接受并退出会自动执行必要检查；③ 生成时每个驱动默认配 `Modelica.Blocks.Sources.RealExpression`=1，真实运动需替换为 `TimeTable` 并设 `驱动类型`；④ 默认包名 `Default`+数字(Default1)（`mcp-workflow.md`）；⑤ 商用 CAD 导入产生**红色未知运动副**，生成前必须 `ModifyUnknownConnector` 修正/删除；⑥ 流体须**导入前先切流体台**、`NumGauge`=0、多油箱手动连接、曲面零件先 `ThickenSurface`（`fluid-elements.md`）。
- **触发描述（description）重写为"条件优先"**。改为先讲清触发条件（用户**已有几何文件**且想转成 Sysplorer 可仿真 Modelica），再列两条路径与边界。经 skill-creator 触发用例集（20 条，10 正例 + 10 近似负例）评测：**precision=100%**（近似负例——纯文字手写、FEA、格式转换、纯查看零件数/体积、改参数重仿——全部正确不触发）；recall 的低值经核实为评测框架在本机并行时的"同名临时技能互相误判"假象（单条无并发 smoke = 100% 触发），非描述问题。最终描述按人工判断择优（非噪声分数）。评测产物保存在配套研究工作区 `ty-cadtool-modeling-workspace`（`trigger-eval.json`、`desc-opt/`；同样仅供留档、不随 skill 分发）。
- 配套修复 skill-creator 工具在 Windows 上的 4 处不兼容（`.claude/skills/skill-creator/scripts/`）：GBK 读取中文（改用 `PYTHONUTF8=1`）、`subprocess` 无法解析 npm `.cmd` shim（`utils.resolve_claude_exe` 跳到真实 `claude.exe`）、`select()` 读管道（改后台读取线程 + 队列）、触发检测在 agent 先探索时误判（改为仅在终止 `result` 判否）。

## v1.2.0 (2026-06-14)

实测 v1.1.0 的测量方案又暴露两个工程问题，均依据源码核对（并经对抗性验证纠正了一处早期误判）：

- **分组后测量报错 → 确立"先测量、后分组"顺序铁律**。根因：`GetGeometricElementIdsOfPart` 按零件**当前点分路径**解析（`GetEntityByNamePath` 走实时 owner 链，`py_command_handler.cpp:7068`），分组会 re-parent 零件、改变其路径（`Pin_6.Pin_7`→`rocker.Pin_7`），沿用旧路径即报 `The part "..." does not exist!`。关键纠正：分组**不会**重命名零件 leaf（`MovePart2Group` 仅 `RemoveSubPart/AppendSubPart`，无 `SetName`，`mbs_data_command.cpp:1877`），且**世界坐标对分组不变**（mId/OCAF 路径、AIS 位置、`mOriginalTrsf` 均不被分组改动）。因此方案：导入后立刻测量、把世界坐标**存成数字**，再分组，再用数字建副；若必须分组后测量，先 `GetParts("<group>")` 查到新路径，绝不猜 `<group>_1`。（`Measure` 自身按 leaf 扁平解析，旧 id 分组后仍可用，但路径型枚举接口是坑。）
- **特征难取 → 明确"盲态"事实 + 提供发现助手**。源码确认 CADToolbox **无**任何截图/取图 API（`ImageFile::WriteFlie` 仅生成 .mo 图标内部用，未暴露给 Python）、`GetGeometricElementIdsOfPart` **无**圆边过滤（只按 Face/Edge/Vertex 返回全部、仅索引）、单个圆柱**面**测量只给 `Radius`/`Perimeter`（无圆心/轴）。故 agent 只能"枚举边→逐个 `Measure`→留有 `Center Position` 的圆边→按半径/同轴聚类配孔"。新增内联助手 `circular_edges`/`bore_axis`（把盲态枚举变成一次结构化结果），并把"用户能从 CAD 图纸读到坐标时优先直接用"列为一等快路径。
- 同步更新：`references/joint-placement.md`（新增"顺序铁律""盲态找特征"两节 + 双段实例 + 助手）、`SKILL.md`/`SKILL_ZH.md`、`workflows/build-multibody-from-cad.md`（步骤重排为测量在分组前）、`references/common-errors.md`、`templates/run-script-skeleton.md`（拆为 B1 测量 + B 分组建模两段）。

## v1.1.0 (2026-06-14)

实战反馈修复两类问题，均依据 CADToolbox 源码核对：

- **运动副位姿靠"猜"→ 改为"测量驱动"**。新增 `references/joint-placement.md`：MCP 下 agent 无法看 3D，必须用 `Measure` 从几何读出坐标——单条圆边返回 `Center Position`(圆心)+`Radius`、单个顶点返回 `Vertex Position`、两特征返回 `Coaxial`/`Concentric`/`Parallel`/`Angle` 用于验证；位置直接取圆心，姿态由"同轴两圆心连线=轴向量"换算欧拉角。明确约定：coord 为**世界系米**、姿态为**外旋 XYZ 度**、运动副功能轴=**局部 +Z**（证据：`mbs_marker_base.cpp` `SetEulerAngles(gp_Extrinsic_XYZ,…)`、`trsf_calculate_util.cpp` `CalXyAdaptiveParallel` 用 `gp_Quaternion((0,0,1), z_vec)`、`LENGTH_SCALE=1000`）。附闭式助手 `axis_to_euler` 与可直接粘贴的 run_script 骨架 `B2`。
- **逐个加固定副 → 改为"先合并分组"**。强化不变量：**一个刚体=一个组**，互固定零件用 `CreateGroup`/`MoveToGroup` 合并，**绝不**用 `ConnectorFixed` 互连；`ConnectorFixed` 仅用于把**一个**体锚定到 `"Ground"`（健康模型有且仅有 1 个固定副，second_entity 为 Ground）。原因：生成时平面环识别 + 自动切割铰（`mo_planar_loop.cpp` 在 `MultibodyModelLayout::AfterLayout` 调用）走的是**"组"邻接图**——把一个刚体拆成多组+固定副会污染该图，导致平面环识别失败、不生成切割铰、模型过约束。同时澄清：**平面环（转轴平行）+ 分组干净 → 生成时自动切割，无需手动**（如 `crank_rocker_mechanism`）；仅**空间环**（轴不平行，如 `ball_four_link`）或自动识别失效才手动 `PlanarLoopConstraint` / `RevolutePlanarCut`。
- 同步更新：`SKILL.md`、`SKILL_ZH.md`、`references/multibody-elements.md`、`references/common-errors.md`、`workflows/build-multibody-from-cad.md`、`templates/run-script-skeleton.md`。

## v1.0.0 (2026-06-12)

- 初始版本发布。
- 覆盖同元 CAD 工具（`mworks.sysplorer.CADToolbox`）经 Sysplorer MCP 的几何驱动建模：
  - **多体**：导入几何 → 分组 → 运动副/驱动/标架/参考标架/设计点/接触/重力/材料 → CheckDesign → 生成 Modelica（TYMultibody）模型 → 检查/翻译/仿真/读结果/动画；含平面闭环切割铰（`PlanarLoopConstraint` 与 `TYMultibody.Joints.RevolutePlanarCut`）处理。
  - **流体**：油箱切片（简单/完整）、肋板切片、流体端口、介质、切片勾选 → 生成流体模型。
  - **迭代设计**：`OpenModelInCadBrowser` 整体/局部迭代（仅多体）。
- 文件构成：`SKILL.md`（英文执行主文件）、`SKILL_ZH.md`（中文审核镜像）、`使用说明.md`、`版本说明.md`、`skill_info.json`，以及 `references/`（mcp-workflow、api-reference、multibody-elements、fluid-elements、common-errors）、`workflows/`（build-multibody-from-cad、build-fluid-from-cad、iterate-existing-model）、`templates/`（run-script-skeleton）。
- 与 `ty-mechanical-modeling` 明确分工：本 skill 处理**有几何文件输入**的转换；纯文字需求的 TY 库手写建模仍走 `ty-mechanical-modeling`。
- 接口、参数、枚举、`attr_params` 键、生成模型命名（`<包>.<模型>.<模型>_main`）均对照 `src/python/python_api/CADToolbox/CADToolbox.py` 与 `src/python/test_use_case/` 真实脚本核对。
