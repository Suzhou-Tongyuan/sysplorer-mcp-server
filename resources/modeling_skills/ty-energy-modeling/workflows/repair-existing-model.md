# Repair Existing Model

1. Existing concrete failures belong to the independent debugging entry defined by the parent; this workflow contributes energy-specific diagnosis, not a fresh build. A failure during new construction remains in the original task. Identify the failing gate and exact diagnostic.
2. Confirm the energy subsystem respects its assigned libraries and retain parent-selected standard/support-domain components. Use parent shared standards for session/error/retry classification and automatic-layout writeback boundaries.
3. Inspect topology, interfaces, and boundary completeness first.
4. Repair the smallest affected parameter or structure.
5. Re-run only affected gates up to the requested terminal stage; no automatic simulation, proxy results, plots or formal reports. Follow parent Gate 6 for actually changed graphical objects.
6. Record evidence, limitations, and whether the model is now stable.
