# 输出契约

## 职责

本文件只定义证据表达方式。四类完成事实、工具阶段与最低证据统一见 `acceptance-checklist.md`，不要在模板或结论中另加完成门槛。

## 必要输入与结论

复用用户已给出的库级目标、现有对象、允许改动、交付粒度、工具链和语言范围。缺失信息不影响本轮时按合理假设继续；不要求用户逐项重填。

结论按实际规模简述：

1. 本轮请求与完成层级。
2. 实际方案/文件及结构或接口影响。
3. 适用的 Examples / Tests、图面与真实验证证据。
4. 尚未满足的请求项或已知限制。

不要求每次输出固定七段，也不自动生成报告。独立文档和成套包装仅在请求时使用 `templates/reports/`、交付或阶段模板；代码骨架可用于已授权建库。

## 状态与证据字段

- 同时给出请求的终端阶段和实际达到的阶段；已达到请求终点即可说明该任务完成，不用运行级门槛否定文件级成果。
- load/open、check、translate、simulate、result verify 分别记事实。未要求记 `not_required`；已要求但未执行记 `blocked`（说明未执行原因）；已执行失败写真实错误和剩余影响。
- `plan-complete`、`files-modified`、`structure-level-verified`、`run-level-verified` 按验收清单选择，不能因文件存在或 check 成功上调为运行通过。
- 模板/接口相关结论只描述实际采用方案与受影响接口；原生标准库接口在模板外兼容项目中不自动成为缺陷。
- 图面触发、覆盖层级和证据形式服从父级 Gate 6。结构化坐标/线段证据不能冒充实际看图；未修改图形对象时不额外要求图面材料。
- 结果只在明确验收、分析或异常诊断时报告必要变量；本轮仿真失败不能用旧结果掩盖。存在插值、区间外端点或回退 warning 时如实说明来源。
- 必要类/参数说明与既有文档链接可随改动维护；正式 Documentation、独立 Markdown、曲线、动画不因模板字段存在而自动创建。

## 证据组织

| 层级 | 可引用证据 |
| --- | --- |
| 方案/评审 | 受评范围、结构建议、问题位置及依据 |
| 文件 | 实际路径、局部改动及引用/目录一致性 |
| 结构 | 检查对象、静态规则和发现；模板采用情况 |
| 工具 | 本轮实际加载/检查/翻译/仿真返回、所需结果与未覆盖对象 |
| 图面 | 本次改动对象、适用 Gate 6、结构化证据及实际获得的图片 |

MCP 0.4 保存后核对 `saved_path`；原位 save 与 save_as 不混用。检查可能自动布局写回，交付需记录实际图形改动和持久化状态。源码离线适配与目标部署/真实回归分别声明。
