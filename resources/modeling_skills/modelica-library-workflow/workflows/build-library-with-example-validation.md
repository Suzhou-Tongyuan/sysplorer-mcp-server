# 构建模型库并完成首个示例验证

## 适用场景

- 用户要求“建一个模型库并给出可运行示例”。
- 用户明确要求“首版可用”“示例运行验证”，或已约定示例/测试的加载、检查、翻译等真实验证阶段；仅交付示例/测试文件不触发运行。
- 任务既包含模型库结构整理，也包含首个 `Examples` / `Tests` 入口的真实验证。

## 核心原则

1. 先做最小闭环，不先铺开大批量业务包。
2. 先稳定顶层结构与公用层，再进入首个业务包。
3. 先验证本轮约定的首个 Examples / Tests，执行到请求终点；只请求一个示例时不追加测试套件。
4. 若任务同时包含物理建模和仿真调参，本 workflow 只负责库结构、示例入口和验证口径；深度建模循环交回父 skill 或领域 skill。

## 步骤

1. 复用 `references/shared-standards.md`，读 `references/executor-base.md`；仅分类不明时补读 mapper。
2. 记录本轮验证对象与终端阶段：load/open、check、translate、simulate 或 result verify，不能把“已验证”自动扩大为全部阶段。
3. 确定正式库名、实际采用的结构、必要公共层和首批业务包。
4. 只建立约定的 Examples / Tests 入口，按 `references/workflow-checklist.md` 的相关章节完成静态检查。
5. 需要 live access 时继承父级会话与 MCP 0.4 契约；确认检查/翻译/仿真的自动布局写回在授权范围内。
6. 执行顶层加载/打开及请求对象的所需检查链，到请求终点停止；可运行声明必须有本轮真实仿真证据。
7. 仅当结果验收、KPI 或异常诊断 required 时读取必要变量；仅要求 simulate 成功时不主动设置 `verify_result_var`，不靠旧结果证明本轮成功。
8. 自动布局实际修改的图形对象按父级 Gate 6 验收；检查成功不等同于图面通过。
9. 按 `references/acceptance-checklist.md` 与 `references/input-output-contract.md` 记录各项真实状态和证据。

## 停止条件

请求范围内的加载、检查或后续阶段失败时，记录真实失败，按父级分类修复策略处理；无新增证据时停止原策略。未请求的后续阶段记 `not_required`，不当作阻塞。结构未稳定时先收口受影响的接口/入口，不扩大到无关案例或重新执行整套建库。

## 输出重点

1. 当前交付停留在哪一层：方案、文件、结构、首个示例验证、运行级验证。
2. 首个 `Examples` / `Tests` 入口的真实状态。
3. 哪些库结构已经稳定，哪些还不应继续扩展。
4. 当前终点是否达到用户请求；剩余阶段是范围外、未执行还是实际阻塞。
