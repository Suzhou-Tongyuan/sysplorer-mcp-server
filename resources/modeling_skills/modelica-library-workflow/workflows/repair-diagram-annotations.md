# 修复图面注解

## 适用场景

任务明确涉及库级图面整理，或库结构/公共接口变更需要修复相关图形对象。普通单模型的“图上没线”“布局很乱”由父级及领域处理；已有具体故障由父级调试入口主导，本 workflow 仅提供所需库级支持。

## 步骤

1. 复用 `references/shared-standards.md` 的父级 Gate 6 与 MCP 副作用约定；只读取 `references/common-errors.md`、`references/workflow-checklist.md` 中图面相关章节。
2. 界定本次新建或实际修改的图形对象；未修改的继承对象与层级不展开验收。
3. 检查 connector 实例的 `Placement(...)`、`iconTransformation(...)`，应显示连接的 `annotation(Line(...))`，以及必要 `Diagram(coordinateSystem(...))`。
4. 保留有意义的现有图标与图面；接口贴边、主体比例、标签避让、主链与测量/控制支路分层作为本地检查项。
5. 采用结构化坐标、端口、线段与文本证据；只有已取得图片并实际检查时才写目视结论。用户要求图片时按父级 ExportDiagram 路径执行或明确能力阻塞。
6. 注解语法/结构错误由模型检查处理；纯视觉问题不阻断检查、翻译或仿真，但完整图形交付前完成适用 Gate 6。
7. 若工具自动布局写回，记录图形改动、落盘与会话持久化证据；check 通过不等同图面通过。
8. 按 `references/input-output-contract.md` 报告修复范围、证据形式、实际验证与剩余风险。

## 模板优先级

优先级从高到低：

1. 现有模型里可保留的图面注解
2. 已整理好的同类模型图面风格
3. Modelica 标准库中同语义组件的图标与图面布局
4. 通用图面修复规则

## 输出重点

1. 缺失的是哪类图面注解
2. 本次修补了哪些位置
3. 是否已经消除了“只有 `connect(...)`、没有 `annotation(Line(...))`、图上看不到线”的问题
4. 是否已经达到“接口贴边、主链路清楚、标签不压线”的最低交付标准
5. 还有哪些图面风险未闭环
