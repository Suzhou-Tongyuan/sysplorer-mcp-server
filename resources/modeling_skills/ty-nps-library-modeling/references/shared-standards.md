# Shared Standards

NPSLibrary 建模的全局执行约束。

---

## 1. 串行规则

- 所有步骤必须按顺序执行
- 前一步 checkpoint 未通过，不得进入下一步
- 失败后必须进入修复闭环，再回到失败步骤
- 不允许跳过需求识别直接建模

---

## 2. 输出规则

- 每一步都必须输出结构化中间结果，但默认优先在对话中输出，不额外落盘保存过程文件
- 关键假设必须单列
- 组件替代必须写明理由
- 结果校核必须回扣用户目标，而不是只描述波形
- 若用户只需要最终模型文件，默认不得创建过程文件、阶段报告、验收报告或修复日志文件
- 默认只保留一个最终模型文件，除非用户明确要求多个交付物
- 若用户已明确指定拓扑或关键组件，默认不得擅自删改；应先在 `NPSLibrary` 内继续查找其它组件类型或类路径
- 连续两轮及以上无根因验证的试错，视为盲猜迭代，必须停止完整模型修改并切换到组件级最小验证

---

## 3. NPS 建模规则

- 优先搭建最小可运行闭环
- 先完成最小闭环，再逐步优化到最终需求目标
- 优先使用 `NPSLibrary`
- 这是 `NPSLibrary` 建模场景；除非用户明确要求，否则不得混用其它电力系统库组件
- 对未知组件，先查清行为再建模；未确认接口、参数、旋转或内部结构前，不得在完整模型上盲目试错
- 电气系统排障时，`Ground / Reference` 检查必须作为第一项必查项；先查是否缺失、重复、接错侧或独立电气岛缺参考，再继续查其它问题
- 当任务目标是图形建模时，优先走 Sysplorer GUI 路径完成组件放置、图标生成、连线和布局
- 当任务目标是图形建模时，不得用 `SetModelText`、`SetModelCode` 或直接改 Modelica 文本替代 GUI 建模
- 图形连线优先使用 `ConnectPort`，不得使用已弃用的 `AddConnection`
- 若图形建模任务绕过 GUI 路径而直接整段写文本建模，必须判定当前建模步骤失败，并禁止放行到 `check`
- 若 GUI 侧建模是通过 `call_code` 发起的，则 `call_code` payload / `python_source` / JSON 格式错误必须先修复，不得直接降级为整段文本建模
- 在最小 `call_code` 验证未通过前，不得使用 `SetModelText`、`SetModelCode`、整段文本注入或 `load_file` 后补丁式改文本作为 GUI 建模替代路径
- 三相系统必须明确相序、接线方式、相电压/线电压定义
- 高频开关系统必须明确开关频率、采样周期、控制周期
- 并网系统必须单独检查 `PLL`、滤波器、并网点和功率方向
- 潮流系统必须明确 `Powergui`、`LoadFlowBus`、P/Q 约束与基准电压
- 电机驱动系统必须检查坐标变换、极性、角度与机械负载方向

---

## 4. 修复规则

- 不得在报错后直接停止
- 修复必须记录现象、根因、动作、结果
- 修复后必须重跑失败步骤，而不是口头宣布“应该可以了”
- 翻译失败、方程冗余、方程缺失、结构奇异时，优先排查连接、接口转换、接口维度、接地和初始化
- 不得通过删除组件、删除子系统或替换为更简单模型来掩盖连接问题，除非该修改已被证明符合原始需求且理由已记录
- 单相/三相、一维/三维、标量/向量接口不匹配，必须作为独立问题处理，不能通过改下游方程绕过
- 新增或修改 `connect(...)` 后，必须同步维护图面 `annotation(Line(points=...))`
- 图面复核一旦早于后续连线修改，就自动失效；修改连线后必须重新复核图面
- 未证明“关键 `connect(...)` 与 `annotation(Line(...))` 仍一一对应”前，不得放行到 `check`
- 对电气接口连线，黑色默认视为待解释状态；若无库规范例外，优先补成显式 `color={0,0,255}`
- 对图形建模任务，缺少关键 `Placement(...)` 或 `Line(...)` 不是可接受残缺，而是失败状态

---

## 5. Sysplorer 安全约束

- 不要在脚本中调用 `ClearAll`
- 不要在脚本中调用 `ChangeDirectory`
- 模型卸载、打开、保存优先走 MCP `model_manager`
- 会话检查优先走 `session_manager`
