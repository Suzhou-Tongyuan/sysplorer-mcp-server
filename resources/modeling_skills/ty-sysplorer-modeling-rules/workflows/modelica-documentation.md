# Modelica Documentation 工作流

仅在用户明确要求为 Modelica 模型、案例或测试对象生成、编写、更新或同步帮助信息时执行。先读取 `references/modelica-documentation-rules.md`。本工作流不替代现有建模、混合建模或七门闸流程。

## 1. 进入条件与串联顺序

1. 确认请求包含明确的文档动作和目标对象。普通建模、修改、检查或仿真任务不得进入，也不主动追问是否需要文档。
2. 区分“回答官方帮助问题”和“向 `.mo` 写入帮助信息”：前者走 `references/documentation-routing.md`，后者才走本工作流。
3. 确认目标为 Modelica `.mo` 对象。若目标为 Sysblock，说明第一阶段不支持并停止本文档路径，不向 Sysblock 写入替代内容。
4. 独立文档任务只处理文档。开发 + 文档组合任务先完成原有开发及用户要求的验证，再串行执行本工作流；文档步骤不得插入或改变原建模过程。

## 2. 识别任务

记录以下四项；只有无法从对象或请求安全判断时才提出一个最小澄清问题：

- 目标 `.mo` 文件和其中的准确类。
- 场景：模型帮助、案例帮助或测试用例文字设计。
- 操作：新建或同步更新。
- 成果：默认写回 `.mo`；仅在用户明确要求时增加独立 Markdown 导出。

## 3. 选择模板

先按固定优先级确定基础结构：

1. 用户本次提示直接给出的完整结构。
2. 用户本次直接给出的模板或 `.md` 模板。
3. 同步更新时已有帮助信息的有效结构。
4. `templates/documentation/model-help-template.md`、`case-help-template.md` 或 `test-case-template.md` 中与场景对应的内置模板。

再将用户本次提示中的明确增删、格式或内容要求覆盖到基础结构上。若提示只给出局部要求，不得将其误当成完整模板，也不得借此绕过未就绪的内置模板。

读取且只读取选中的模板。内置模板必须同时含 `template-status: ready` 和 `template-schema: modelica-documentation-v1` 才可执行；若状态为 `human-input-required`、状态未知或 Schema 缺失/不匹配，停止写入并报告模板未就绪。内置模板只将 `template-output:start` 与 `template-output:end` 之间的骨架作为默认成品结构，其余字段表、规则和检查清单只用于指导生成，不得复制进 `Documentation.info`。

## 4. 按模板读取事实

1. 从模板提取所需字段和可选增强项，形成只针对本次任务的信息清单。
2. 读取目标类及完成这些字段所必需的直接工程上下文；不要为未采用章节扩大检索、检查或仿真范围。
3. 为每项候选陈述记录证据位置：当前声明、继承/公开类文档、方程、算法、初始化、条件组件、已有合法 Documentation 或已验证结果。
4. 将无证据、冲突或仅凭类名推测的内容标为缺口。商业类只使用公开证据，不读取受保护源码。

## 5. 生成或同步内容

### 新建

按选定模板组织已证实事实；对可选但无证据的内容省略或明确标为未确认。测试用例只写设计，不运行测试、不生成测试报告、不输出 PASS/FAIL。

### 同步更新

比较当前对象与现有帮助信息，建立“对象变化 → 受影响内容”清单。只更新受影响部分，保留仍正确的人工补充、原有结构、链接和真实图片。当前模型事实优先于冲突的旧文字；除非用户要求整篇重写或新模板要求重组，否则不整篇替换。同一 `Documentation.info` 已含其他逻辑场景时不得覆盖；无法可靠识别场景边界则先澄清。

## 6. 一致性检查

写回前核对：

- 类名及对象类型准确。
- 所有参数、默认值、单位、接口及条件启用逻辑真实存在并匹配。
- 行为说明能追溯到实际方程、算法、初始化或公开证据。
- 案例结果区分实际已验证结果、预期结果和未验证内容。
- 测试用例保持为文字设计，没有执行结论或测试报告措辞。
- 测试用例的具体输入、边界、仿真时间和判定阈值有明确来源，未自行选择代表性数值。
- 人工内容未被无依据删除，失效冲突内容已局部修正。
- 图片均有真实来源；图片不可用时纯文字内容仍自洽。

任一必需事实无法确认时，先收缩表述或报告缺口；不得为通过检查而修改模型行为。

## 7. 转换、写回与最小验证

1. 将结构化内容转换为适合 `Documentation(info=...)` 的 HTML，完成 HTML 与 Modelica 字符串转义。
2. 精确定位目标类的类级注解：已有 `Documentation` 时局部更新 `info`；没有时合并新增。保留其他注解、有效字段、编码、BOM 和换行格式。
3. 回读目标类，确认只有授权的帮助内容发生变化，HTML 边界完整，未出现重复 `Documentation` 或误改其他类。
4. 默认回读并静态核对 HTML/Modelica 字符串转义、注解边界及差异，只允许授权的 Documentation.info 变化。MCP 0.4 的 check 可自动布局写回，不能为文档验证直接对原件调用；若确需实时模型检查，按 shared-standards 的授权副本/无写回能力边界处理并说明验证范围。未执行实时检查不得声称已通过；除非组合任务另有授权，不翻译、不仿真、不执行测试。
5. 用户明确要求 Markdown 导出时，再按用户路径或项目约定生成；否则不创建独立 `.md` 成品。

## 8. 独立报告状态

分别报告：目标、场景、操作、模板来源、写回是否成功、一致性检查是否通过、图片状态和剩余缺口。组合任务中另行保留原建模任务的既有状态；文档或图片失败只影响文档状态，不回退已完成的建模结论。
