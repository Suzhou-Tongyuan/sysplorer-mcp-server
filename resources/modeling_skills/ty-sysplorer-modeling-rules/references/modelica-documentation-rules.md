# Modelica Documentation 内容与写入规则

本文件规定显式文档任务的事实、内容和写入边界。执行顺序以 `workflows/modelica-documentation.md` 为准；普通帮助问答仍走 `references/documentation-routing.md`。

## 1. 能力边界

- 第一阶段只处理 Modelica `.mo` 对象：模型/基础组件、Example/Demo/完整案例、测试用例文字设计。
- 只在用户明确要求生成、编写、更新或同步帮助信息时进入；普通建模结束后不自动生成、更新、询问或推荐。
- 默认成果写入目标类的 `annotation(Documentation(info=...))`，不额外创建 Markdown 成品。只有用户明确要求时才另行导出 `.md`。
- 文档任务主要读取已有开发成果。发现模型问题时报告问题，不为使文档成立而修改方程、参数、接口、拓扑或行为。
- 文档任务与建模任务独立成败；图片或文档写入失败不得抹去已经成立的建模、检查或仿真结果。
- 第一阶段不为 Sysblock 生成或写入本体系的帮助内容。后续 Sysblock 文档能力必须单独设计存储和写入机制。

## 2. 场景语义

| 场景 | 文档目的 | 明确排除 |
|---|---|---|
| 模型帮助 | 说明单个模型或基础组件的真实功能与使用信息 | 不按类名猜测接口、参数或行为 |
| 案例帮助 | 说明 Example/Demo/系统案例的真实组成、使用方式和已有结果 | 不把未执行仿真写成实际结果 |
| 测试用例 | 记录测试目标、条件、步骤、观察对象、预期结果和判定要求等文字设计 | 不执行测试，不生成测试报告，不判定 PASS/FAIL |

三类场景只在内容目的和所选模板上不同；最终均转换为适合 Modelica 的 HTML，并写入同一 `Documentation(info=...)` 承载位置。

## 3. 模板与信息获取

模板只定义写什么、如何组织以及需要读取哪些工程信息，不代表最终存储格式。先按以下顺序确定基础结构：

1. 用户本次提示直接给出的完整结构。
2. 用户本次提供的模板，包括 `.md` 模板。
3. 同步更新时已有帮助信息的有效结构。
4. 对应的 Skill 内置默认模板。

再把用户本次提示中的明确增删、格式或内容要求作为最高优先级覆盖基础结构。提示只给出局部要求时，不能把该局部要求误当成完整模板，也不能借此绕过尚未就绪的默认模板。

只收集当前选定模板需要的信息。不得因内置模板还有其他章节而擅自扩展用户模板，也不得为未采用的章节额外检查或仿真。

`templates/documentation/` 下三个内置模板统一使用 `modelica-documentation-v1` 结构：

- 以 HTML 注释声明 `template-status`、`template-schema`、`template-scene` 和 `output-target`。
- 固定包含“模板契约、字段与事实来源、默认输出结构、章节生成规则、图片增强、专项一致性检查”六部分。
- 使用 `{{中文字段名}}` 占位符和统一的 GFM 表格；只把 `template-output:start` 与 `template-output:end` 之间的骨架生成结果写入成品。
- 模板说明、事实表、章节规则、图片规则、检查清单、边界标记和未替换占位符均不得进入最终 `Documentation.info`。

三个内置模板当前均标记为 `template-status: ready`。若内置模板被改回 `human-input-required`、缺少统一 Schema 或状态未知，按工作流停止写入，不得自行补写或猜测模板结构。用户模板或可沿用的已有结构不受内置模板状态影响。

## 4. 事实来源

1. 以目标 `.mo` 当前可见的类声明、参数、变量、连接器、继承、方程、算法、初始化、条件组件和注解为首要事实。
2. 需要理解继承或引用类时，只使用实际可访问的工程源码、公开类文档、公开内省和已登记语料。受保护商业库仍遵守禁止解密、反编译、解包、源码提取或解析的边界。
3. 参数名称、默认值、单位、接口名称与数量、条件启用逻辑、初始化、Reset/Set 行为、结构及结果都必须有当前工程证据。
4. 模板决定组织方式，真实 Modelica 对象决定可写事实。类名、常识、旧文档或模型先验都不能替代当前对象证据。
5. 测试用例中的具体输入、边界、初值、仿真时间和判定阈值只能来自当前模型、用户要求或已有规范；缺少数值时使用符号条件或标记待确认，不自行选择代表性数值。
6. 对证据不足的内容标记为未确认或省略；不得用看似合理的描述填补缺口。

## 5. 同步更新

- 先比较当前对象、现有 `Documentation` 和选定模板，再定位受变化影响的内容；默认不整篇重写。
- 保留仍正确的人工说明、结构、合法链接和图片引用，不随意删除有效内容。
- 现有文字与当前模型事实冲突时，以当前对象为准，并只修改冲突或受影响部分。
- 仅当用户明确要求整篇重写，或指定新模板确实需要重组时，才重建整体结构。
- 同一 `Documentation.info` 已承载其他逻辑场景时，只处理本次目标场景；若无法可靠识别场景边界，先请求澄清，不得覆盖其他场景内容。
- 不覆盖 `Documentation` 中与 `info` 并列且仍有效的其他字段，也不重复创建类级 `Documentation` 或最终 `annotation`。

## 6. HTML 与写回

- 先按选定模板形成结构化内容，再转换为 `info="<html>...</html>"`；Markdown 模板不是默认成品格式。
- 生成有效、克制的 HTML；正确转义 HTML 特殊字符和 Modelica 字符串中的引号、反斜杠及换行，不把 Markdown 标记原样塞入 HTML。
- 将内容合并到目标类现有的类级 `annotation(...)`。已有 `Documentation` 时精确更新 `info`，保留仍有效的其他注解与格式；没有时才新增。
- 精确、局部写回并保留原文件编码、BOM 和换行风格。写回前后都确认目标类，避免误改同文件中的其他类或嵌套对象。
- 写回后以回读、HTML/字符串转义和注解差异静态检查确认目标帮助内容；文档修改不授权其他注解或行为变化。实时 check 可能自动写布局，按 modelica-documentation 工作流和 shared-standards 的副作用边界处理，不直接对原件调用；文档修改本身不授权翻译、仿真或测试执行。

## 7. 图片与一致性

- 模型和案例可在模板要求且能力可用时增加真实图片；测试用例默认不依赖图片。
- 不得虚构 Sysplorer 截图、模型结构图、参数界面或仿真曲线。图片不可得或处理失败时，继续生成纯文字内容并单独记录缺口。
- 最终逐项核对名称、参数、默认值、单位、接口、条件启用逻辑、行为依据和结果表述。未经实际验证的结果只能标为预期或未验证，不能写成实际结果。
- 同步更新后不得保留已失效且与当前对象冲突的内容。证据或写入不足时，准确报告剩余缺口，不把文档任务标记为完成。
