# 文档路由与降级规则

本文件只规定“为了回答问题或支撑下一步建模决策，应使用哪类文档和工具”。它不授予构建、检查、翻译或仿真权限，也不替代 Modelica、混合建模或领域 Skill 的执行工作流。用户明确要求为 `.mo` 对象生成或同步 `Documentation(info=...)` 时，不走本文的帮助问答路径，应改读 `references/modelica-documentation-rules.md` 和 `workflows/modelica-documentation.md`。

## 1. 先按信息类型选择来源

| 信息需求 | 首选来源 | 不可替代的边界 |
|---|---|---|
| 官方帮助中心中的概念、教程、原理、故障原因、最佳实践或产品操作说明 | `sysplorer-mds-docs` 及当前可用的 MDS 搜索 | 仅适用于纯帮助问答或用户明确要求先查官方帮助 |
| 一个已加载类的参数、端口、连接器和类说明 | `get_lib_model_document` | 不用 MDS 或语料猜测具体类面板 |
| ModelingPy/API 的函数签名、参数和用法 | 先实时发现，再使用 `get_api_document` 或 `ListFunctions` | 不把旧文档中的静态签名当作当前 API 事实 |
| 已登记的本地或部署语料 | `resources_retrieval` | 搜索结果是证据线索，不等于受保护源码 |
| 受保护商业类的行为或端口补充证据 | 类文档、公开内省和最小黑盒验证 | 禁止模型文本提取、解密、反编译或源码解析 |

## 2. 纯帮助问答的 MDS 优先路径

1. 只有用户的主要目标是纯帮助问答，或明确要求查阅官方帮助时，才由 `sysplorer-mds-docs` 优先处理。
2. 仅在当前工具列表中确有 MDS 搜索能力时才调用；若该工具要求登录，登录不可用应作为可审计的失败事实记录。
3. MDS 搜索的 `query` 应改写为约 100 字符的“假设性答案/用户将获得什么说明”，而不是直接复制用户原问题或只提交关键词。
4. 单个已加载类的端口和参数优先改用 `get_lib_model_document`；API 签名优先改用实时发现和 `get_api_document`。不得为这些精确信息强行调用 MDS。

## 3. MDS 失败后的降级路径

只有 MDS 未完成纯帮助问答，并能说明失败、不可用或无结果时，才执行以下降级；MDS 失败本身不构成任何模型修改授权：

1. 明确说明帮助中心文本未取得的原因或范围。
2. 以问题的产品、类、功能和错误现象为线索，在 `resources_retrieval` 中搜索相关已登记语料。
3. 若问题涉及已加载类或 API，补充读取 `get_lib_model_document` 或实时 API 文档。
4. 分别总结已获证据、无法确认的内容、冲突信息和剩余缺口；不得把推测表述为官方结论。
5. 对纯帮助任务到此结束：不得构建模型、执行 `check_model`、翻译或仿真。

## 4. 建模任务中的文档使用方式

当主要目标是创建、修复、检查、仿真或交付具体模型时，建模 Skill 和领域 Skill 保持主责。文档检索只支撑当前下一项决策，例如确认类、端口、参数、单位、连接器、API 调用或商业库边界；不得因 MDS 不可用而阻塞路径判断、模型检查或 Gate 6。

建模回复中应记录：查询过的类/API/语料、采用的结论、拒绝或不确定的候选，以及该信息对下一步决策的影响。
