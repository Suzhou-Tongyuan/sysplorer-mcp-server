# 模块参数对象映射说明

`GetModelParamValues` 的完整读取流程不只是返回底层 JSON，还会根据模块类型尝试做对象化转换。

核心规则只有一条：

- 只有在 `block_params.py` 中定义并注册到 `BLOCK_PARAM_CLASS_MAP` 的模块，完整读取时才返回 DataClass。
- 未在该映射表中注册的模块，统一按 `dict` 返回。

## 1. 映射来源

映射定义位于 `block_params.py`，当前已确认的注册关系为：

```python
BLOCK_PARAM_CLASS_MAP = {
    "CCaller": ExternalCFunctionConfig,
}
```

这表示当 `GetComponentTypeName(modelName, component)` 返回 `CCaller` 时，读取结果会尝试转换为 `ExternalCFunctionConfig`。

## 2. 当前已覆盖模块

- `CCaller`
  - 对应 DataClass：`ExternalCFunctionConfig`
  - 典型字段：
    - `HeaderFile`
    - `FunctionName`
    - `SampleTime`
    - `ArrayLayout`
    - `Arguments`

## 3. `FunctionField` 结构

`CCaller` 的 `Arguments` 字段中，单个参数对象当前已确认至少包含以下字段：

- `CName`
- `MoName`
- `IOType`
- `DataType`
- `Dimension`
- `Value`
- `Description`

## 4. 扩展方式

后续如果新增复杂模块类型，应优先按以下方式扩展：

1. 在 `block_params.py` 中新增对应 DataClass。
2. 将模块短类型名注册进 `BLOCK_PARAM_CLASS_MAP`。
3. 维持字段名与底层 JSON key 一致。
4. 继续通过 `GetModelParamValues` / `SetModelParamValues` 统一读写。

## 5. 边界说明

- 对象化转换属于公开接口的内部行为，调用方不需要自己处理底层序列化细节。
- `Utils/param_normalize.py` 负责归一化与转换支持，但不作为独立外部 API 暴露。
- 传入 `fields` 时不会触发 DataClass 映射，返回值固定为 `dict`。
- 如果调用方拿到的是标准模块配置，请直接按 `dict` 读写，不要假设存在属性式访问。
