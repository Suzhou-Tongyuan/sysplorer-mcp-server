# Sysblock 模型调试

已有 Sysblock 的组件、端口、连接、参数、采样时间、仿真、代码生成、生成求解器构建或 CCaller 具体故障直接触发。普通新建、布局、无故障整定和纯 API 查询不触发。

普通 Sysblock 修改/交付引用 `ty-sysblock-diagram-modeling` 的接口、布局、保存/重载和审计约束，信号任务按需补充信号 Skill。只有修改物理顶层时才引用物理主 Skill。读取约束后保持当前调试步骤，不重启流程。

## 诊断与修复顺序

1. 读取相关模型身份、结构、源码/哈希及用户验收，检查 FQN、restriction、首错阶段；只检查故障块、直接邻居和必要信号范围。简单故障约 12 次调用只是成本参考，不替代必要验证。
2. 区分打开/检查、仿真、代码生成、预处理/编译/链接及 CCaller 外部调用；check 失败不继续。复现到首个失败阶段，不假定某个仿真或代码生成 API 适用于全部求解器构建。
3. 明确假设后仅在修复模式应用最小结构化修改或用户 C 源码补丁，读回后复验用户要求的同一终端阶段。基线在声明故障之前因环境失败时报告待验证，不根据猜测修改。

## 结构化可逆编辑

- 禁止用 SetModelText、手写 Modelica、connect() 或生成文件修改 Sysblock 拓扑。
- 修改前按影响范围快照组件、端口、连接、标量参数、完整参数 DataClass、资源列表和目标设置。复杂对象整体合并目标字段后写入一次，再读回相关字段；旧值不能读取或恢复时不自动写入。
- 未知接口使用框图 `scripts/api_contract_resolver.py` 和 `references/runtime-contracts.md` 确认。故障参考按需读 `references/sysblock-diagnostics.md`；副本/回滚按需读 `references/current-mcp-recipes.md`。
- 拓扑/布局变化遵守框图规划与结构化几何读回，修改后保存并重载最终模型，执行适用审计。仿真成功不替代保存模型证据；纯 C 代码修改不触发布局编辑。
- 禁止修改 wrapper、生成 C、工程/求解器输出以及受保护第三方源码。

## CCaller 与帮助

按 `references/external-c-debugging.md` 关联完整 CCaller 配置、资源、公开签名和首条构建/运行证据。保护参数顺序、方向、类型、维度、数组布局、采样时间及资源注册；只修用户工作副本中有证据的接口、资源、边界或符号问题。

不得因为知道测试值而编造常量或删除外部依赖。未解析符号应找到正确实现/链接，或获得新的设计授权。代码生成成功不代表编译/链接成功；链接限定任务复验链接，功能恢复/异常结果任务核验实际调用或下游 KPI。

FAQ 按 `references/help-doc-index.md` 和 `scripts/query_sysplorer_help.py` 匹配产品编号和类别，进程/编译器返回码使用嵌套具体诊断。公开块语义用 `get_lib_model_document`，本地帮助缺失或无匹配后回退 `resources_retrieval`。消息可能覆盖/截断，只报告本轮可归属证据。

## 任务模式与共用边界

- 入口独立触发，不要求先经过建模主入口或调试总入口。明确领域时直接使用专业调试 Skill。
- 根据请求区分 `diagnose_only` 与 `repair`。只解释/定位问题不授权补丁；仅在请求允许时复现，明确离线审查不执行模型。证据不足如实报告，不将假设称为已解决。
- 记录用户要求的终端阶段及验收条件，复用可归属当前模型和设置的基线、会话、工作副本与检查点。引用其他 Skill 的约束后返回当前步骤，不再次分流、重规划或重复复现。新建过程中的故障处理完后继续原建模任务。
- 离线模型/日志读取不调用会话工具。首次实时访问经 Sysplorer MCP 确认目标，支持时先 `probe` 再 `health`；同一有效会话可复用，切换、断连或基础设施异常后重查。所有 ModelingPy 调用只经 MCP，本地辅助脚本只处理文件。
- 当前已知 API 契约直接复用；未知名称、参数和返回类型在调用前定向确认，文档为空按准确名称查询 Help/签名或对应工具箱文档。不得猜测写入、在目标模型试探未知写接口或全量枚举 API。
- 保护原模型、原 C 源码和未保存 GUI 状态，修复只写已核验的任务自有副本。不用 `extends Original` 冒充副本，不修改生成代码或受保护商业库源码，不以删除断言或扫求解参数掩盖缺陷。
- 现有明确授权继续有效；新增实质性设计或范围变化才请求用户判断。同一假设两轮无改善后停止该策略，转入有用的定向证据或最小案例；相同基础设施操作失败两次后停止重复重试，报告缺口，不为凑次数继续猜测。

## 按范围验收与报告

详细状态见 `references/report-contract.md`。只诊断有充分证据时用 `diagnosis_complete`，说明根因已确认还是仍为假设，不宣称修复。证据不足用 `verification_required`。

修复必须有补丁读回、所需静态及终端阶段通过、原件保护和临时设置恢复。静态/链接验收不自动要求仿真或 stopTime；运行验收达到约定原终点；只有用户要求或异常结果所必需时才读取结果和核验 KPI，否则标记 `not_required`。实际变更图形对象仍完成对应建模交付检查。范围内验证通过用 `verified_solved`；有可重复改善但未完成用 `partially_improved`；必要证据缺失用 `verification_required`；无可继续的授权/能力路径用 `automatic_debugging_stopped`。
