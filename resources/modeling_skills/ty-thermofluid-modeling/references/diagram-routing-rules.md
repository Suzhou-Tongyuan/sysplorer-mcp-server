# 图面连线规则

本文补充父 Gate 6 适用图形对象的走线质量，包括过程、热和控制连接。仅验收本次新建/实际修改对象（含自动布局写回），未触及继承层级不展开；不适用时记 `not_required`。纯视觉缺陷不阻塞 check/translate/simulate，图形语法/结构错误由检查阻断。

## 1. 通用原则

- 所有连线都应优先走组件外侧空白区域，不得穿过任何组件主体图元。
- 开始连线前，优先调整相连组件的位置，使对应的可连接接口尽量先对齐，再进行连线。
- 若两个组件之间没有其他组件、标签或控制块遮挡，连线应尽量保持纯水平或纯竖直。
- 若必须拐弯，优先使用正交折线，不使用斜线，不做无意义折返。
- 调整图面时，优先移动组件位置，其次才增加折点；不要靠复杂折线弥补布局问题。
- 连线不仅要在模型语义上存在，还必须在图形层明确显示。
- 不接受“模型已经 `connect` 成功，但缺少有效 `annotation(Line(...))`，导致图形层无法渲染连线”的情况。
- 若从坐标和图形注解可判断 `Line(points=...)` 过短、落入组件范围、缩在接口附近，或无法形成可渲染线段，应继续调整 `Placement` 和 `Line(points=...)`；具备图片检查能力时可再做视觉确认。

## 2. 明确禁止的问题

- 连线穿过容腔、换热器、泵、阀、边界、传感器、控制块等组件主体。
- 连线压住组件名称、端口、箭头方向或关键图标。
- 一根长线横穿主设备区域，导致图面阅读路径混乱。
- 本可水平或竖直直连的场景，却画成多段折线。
- 多条连线在无必要情况下重叠、贴边或挤在同一狭窄区域。
- 组件已经连接，但图形层没有可见线段，导致读图时看起来像“没连上”。

## 3. 推荐布局习惯

- 主流道优先按左到右组织。
- 辅助热边界、控制块、传感器优先放在其作用对象附近。
- 同一类辅助组件尽量成排布置，避免一高一低破坏整体视觉节奏。
- 泵的机械接口、阀门开度接口、热口和流体口应尽量分别朝向各自的连线方向。
- 若两个组件直接相连，优先让两侧接口共线；能做到水平对齐就不要先放成错位再用折线补救。
- 若一组串联组件位于同一路支路，优先按接口高度或左右位置成排对齐，再统一布线。

## 4. 连线细则

### 流体连线

- 相邻流体组件若为直接串联，优先让 `port_a/port_b` 在同一水平线上。
- 若中间无遮挡，流体主线优先水平直连。
- 若需要绕开组件，先横后竖或先竖后横，保持正交且折点数量最少。
- 换热器两侧进出口应尽量成对齐关系，避免一侧高一侧低导致回路扭曲。

### 热连线

- 热边界与目标热口应优先先对齐热口方向，再连线。
- 热边界连接热口时，优先放在目标组件的上方或侧上方。
- 若热口在组件顶部，不得把热边界放在组件下方后再让连线穿模回到顶部热口。
- 热连线长度应尽量短，且避免与主流道交叉。

### 控制连线

- 控制源与目标输入口优先先对齐接口高度，再连线。
- 控制源应尽量靠近目标执行元件，避免整张图只有一根超长控制线。
- 若多个执行元件共享同一控制逻辑，但共享一根线会显著破坏图面，可拆成多个就地等效命令源。
- 这种拆分只改变图面表达，不改变控制语义；交付时应说明其来自同一控制逻辑。

## 5. 布局复核

MCP 0.4 导图先查询 `get_api_document("ExportDiagram")`，再按官方参数通过 `call_code(mode="run_sysplorer_api", payload={...})` 调用，不使用旧 manager 导图动作。check/translate/simulate 可能自动布局写回；遵守父 shared-standards 的只读与授权边界。分别记录写盘、官方布线、保存持久化和最终图面验收，不把某一步成功视为全部通过。

默认先检查 `.mo` 中的 `Placement`、`Line(points=...)`、`Diagram(coordinateSystem(...))`、连接器端点和布局工具诊断。图片导出不是强制步骤；只有用户明确要求导图，或导出与图片检查能力均可用且有助于验收时，才导图并追加视觉检查。

结构化审核以及可选的视觉审核应覆盖：

- 是否存在任意组件被连线穿过。
- 是否存在本可直连却没有直连的线。
- 是否存在过长控制线横穿主设备区。
- 是否存在标签遮挡端口、端口方向难辨认的问题。
- 是否存在语义上已连接、但图形层看不到明确线段的连接。
- 是否仍可通过移动组件来减少折点、交叉或不可见短线。

若任一项有明确证据表明存在问题，应回到模型继续调整 `Placement` 或 `Line(points=...)`，而不是直接交付。

若图片导出或图片理解能力不可用：

- 无可用能力时停止反复尝试；用户明确要求图片时单列图片交付未完成及原因，不能静默跳过要求。
- 以结构化审核结果完成布局验收，并注明未执行视觉复核及其覆盖限制。
- 不得声称已目视确认遮挡、标签压盖或整体美观度；也不得仅因缺少图片能力阻塞功能验收或结构化布局验收。
