# 需求映射

本文件用于把用户说法映射为任务类型、优先库和默认执行路径。

## 映射表

| 用户说法 | 任务判断 | 优先库或模板 | 默认路径 |
| --- | --- | --- | --- |
| 帮我搭一个水/油/蒸汽/制冷剂热流体系统 | 新建模型 | `TYThermoFluidSys` | 先确定介质，再按开环主链路落模 |
| 帮我搭一个乙二醇/丙二醇冷却回路或热管理回路 | 新建模型 | `TYThermoFluidSys` + `TYMedia` 或 `Modelica.Media` | 先确认浓度与相态，再按液体单相开环骨架落模 |
| 帮我搭一个暖通/通风/空调/环控系统 | 新建模型 | `TYAirTreatmentAndVentilation` | 先确定气体成分，再按空气处理开环主链路落模 |
| 帮我做空气侧和液体侧换热耦合 | 新建模型 | 联合使用两个专业库 | 先拆空气侧和液体侧，再在换热接口处耦合 |
| 我想直接搭闭环回路 | 新建模型 | 原目标系统相关库 | 默认仍先拆成开环或分段验证，再逐步闭环 |
| 选一个合适的 `TYMedia` 介质 | 介质选型 | `TYMedia` 或 `Modelica.Media` | 先确认相态、成分和相变需求，再选介质 |
| 修一下介质不匹配/`replaceable package Medium` 报错 | 修复模型 | 原模型相关库 | 先识别连续回路介质，再统一介质约束 |
| 修一下连接不合理/检查不过 | 修复模型 | 原模型相关库 | 先查主回路拓扑，再查阻容组织和边界 |
| 修一下干燥器/增湿器/湿空气模型，湿度结果不对 | 修复模型 | `TYAirTreatmentAndVentilation` + 混合气体介质 | 先查气体中是否含水蒸气，再查处理段和传感器 |
| 修一下图面重叠、元件变形、连线难看 | 修复模型 | 原模型相关库 | 先修 `Placement` 和分区布局并做结构化复核；能力可用或用户明确要求时再导图复核 |
| 仿真发散、`NaN`、除零、算不动 | 修复模型 | 原模型相关库 | 先退回开环或分段验证，再排查参数与离散方式 |
| 跑一下样例并看结果 | 样例验证 | 原样例库与模型 | 先检查，再翻译，再仿真，再做关键变量验证 |
| 跑官方/公司样例，判断能不能作为我的系统起点 | 样例验证 | 原样例库与模型 | 先验证样例，再说明哪些部分可继承、哪些部分只可参考 |
| 输出压力、温度、流量、湿度、焓值曲线 | 结果整理 | 原模型相关库 | 先确认关键变量，再读取结果并解释 |

## 任务路径选择规则

1. 用户目标是“从零搭建”时，进入 `workflows/build-from-scenario.md`。
2. 用户目标是“已有模型修复”时，进入 `workflows/repair-existing-model.md`。
3. 用户目标是“现有样例或现有模型验证”时，进入 `workflows/verify-example.md`。
4. 同时出现“新建 + 验证”时，先按新建路径完成骨架，再按验证路径执行本次要求的静态检查、check、translate、simulate 或结果核验，不自动扩到结果读取。
5. 同时出现“修复 + 验证”时，先缩小修复范围，再仅复验受影响且属于本次请求的阶段；文件交付或只读评审不自动触发软件启动，明确请求的实时只读查询按通用动作规则执行，结果仅按请求核验。

## 先确认的输入

- 系统属于热流体回路、空气处理回路还是多域耦合。
- 用户要的是结构建模、参数化、修复、仿真还是结果说明。
- 用户是否明确给出介质、相态、工况边界和关键观测量。
