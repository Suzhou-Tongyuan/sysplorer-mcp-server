# 验证规则 / Validation Rules

用于补充父级已选验证范围内的机械检查项。图面触发、证据和时序以 `../../ty-sysplorer-modeling-rules/workflows/seven-gates-validation.md` 为准：结构化证据为基础，图片按请求和能力补充；纯视觉问题不阻止 check/翻译/仿真，注解语法或结构错误由模型检查处理。

## 标准验证顺序

1. 库边界检查。
2. 组件接口和跨库兼容性检查。
3. 世界与参考系检查。
4. 接口与连线检查。
5. 按需记录图形连线和布局问题，在完整图形交付前完成适用 Gate 6；视觉问题不阻断后续物理检查。
6. 方程数、变量数和自由度直觉检查。
7. 参数与单位数量级检查。
8. `translate` 前的初始化与约束检查。
9. 仅当父流程的验收合同明确要求结果、KPI、曲线或动画时，执行 `simulate` 后验证；否则标记为 `not_required`。

## 建模前静态预检

在调用 `check_model` 之前，先用 5-10 行文字或表格完成静态预检。预检不是形式输出，它用于避免把明显错误交给 Sysplorer 反复试错。

| 预检项 | 做法 | 典型判断 |
|---|---|---|
| 组件接口 | 对主链每个组件列出端口域：rotational/translational/flange/frame/signal | 不同物理域不得直接 `connect` |
| 世界/参考 | 2D/3D/多体必须有世界；1D 链只放必要固定/参考 | 缺世界会漂移；过多固定会锁死自由度 |
| 自由度 | 粗略判断哪些惯量、刚体、质量块应能运动 | 负载惯量不应两端刚性接地 |
| 方程平衡 | 自定义组件先列变量、输入、输出和方程来源 | 控制状态、楼层、按钮等离散变量必须有方程或赋值 |
| 参数数量级 | 用用户给定值或保守默认值检查单位和量级 | 刚度/阻尼/转速过大需说明初值风险 |
| 结果变量 | 仅在用户要求结果核验时，于仿真前列出预计变量名或候选变量名 | 结果读取失败时能快速定位变量名问题 |

## 结构检查项

| 检查项 | 判断标准 | 风险提示 |
|---|---|---|
| 库边界 | 机械子系统使用已选 TY/标准库/用户自建组件；保留项目其他领域已选组件 | 白名单不约束整个交付物，跨域接口需核对 |
| 世界与参考系 | 2D/3D/多体模型已显式放置世界组件，参考系一致 | 缺失世界组件常导致结构不闭合 |
| 平面闭环多体约束 | 曲柄滑块、曲柄连杆、平面四杆等带环机构已将一个转动副替换为 TY 切割铰，并记录替换位置 | 普通转动副完整闭环容易造成约束过强、方程冗余或初始化困难 |
| 接口完整性 | 无漏连、重复连、方向明显错误 | 图形连上不代表物理语义正确 |
| 图形连线完备性 | 每条物理连接均有 `connect(...)`，且 Diagram view 中存在对应可见连线 | 只有方程连接、没有图形连线会降低用户复查和后续编辑效率 |
| 图形布局 | `connect(...)` 应带合理 `annotation(Line(points = ..., color = {95, 95, 95}, thickness = 0.5))` 或 Sysplorer 等价布局元数据；连线应从端口附近出入，交叉和折返最小化 | 过差布局会增加排障成本，不能作为最终交付状态 |
| 方程变量一致性 | 方程数与变量数一致或检查结果表明结构闭合 | 这是交付前的硬性门槛 |
| 参数生效性 | 参数名来自真实查询结果，单位和数量级合理 | 猜测参数名会导致赋值未生效 |

## 高频物理一致性校核

- 一维齿轮传动：若理想齿轮传动比为 `i`，仿真前先写出预期的主动/从动角速度关系和符号约定；结果中转速比应接近该预期。
- 转动惯量负载：惯量是储能元件，需要至少一个未被刚性边界锁死的运动自由度；传感器应尽量不改变主链约束。
- 弹簧阻尼：弹簧/阻尼通常需要相对运动或参考端；若两端都随同一刚体刚性运动，输出力矩可能为零。
- 多体模型：世界、固定件、关节轴和刚体初始姿态应形成可解释装配；动画比单条曲线更容易发现参考系错误。
- 自定义库/场景组件：每个 `model` 单独满足方程平衡后再组合成 package，避免在大系统里排查缺方程。

## 图形连线写法要求

生成或修改 `.mo` 模型时，必须优先采用带图形 annotation 的连接写法。参考格式：

```modelica
connect(revolute1.frame_b, boxBody1.frame_a)
  annotation(Line(
    points = {{-40, 0}, {-20, 0}},
    color = {95, 95, 95},
    thickness = 0.5));
```

检查规则：

- 所有必要端口都必须有实际 `connect(...)` 方程，包括物理端口、信号端口、frame、world/reference、传感器、源和边界条件。
- `annotation(Line(points = ...))` 必须与组件图标位置大致匹配，不得使用明显无意义的坐标。
- 连线不得大量穿过组件图标，不得出现不可读的重叠线束；必要时增加中间折点。
- 同一主链路的组件应按输入到输出、驱动到负载、世界/参考到机构主体的方向组织布局。
- `smart_layout` 自动整理后，仍应复查关键连接是否保持语义清晰。
- 方程级 `check` 通过但图形视图缺线、乱线或布局不可读时，不能判定为可交付。

## 结果验证项（按需）

仅当父流程将结果验证标记为 `required` 时使用本节。

| 场景 | 关键变量 | 判断标准 | 风险提示 |
|---|---|---|---|
| 运动与传动系统 | 位移、速度、角速度、转速比 | 方向、幅值和变化趋势与工况一致 | 异常跳变通常指向约束或参数问题 |
| 受力与驱动系统 | 力、力矩、反力、驱动力 | 量纲正确、峰值可解释、能量输入输出一致 | 过大峰值常见于刚度/阻尼或初值失衡 |
| 接触系统 | 接触力、摩擦力、穿透量 | 接触发生时响应连续，可解释，无持续不合理穿透 | 持续穿透常见于接触参数不合理 |
| 多体与空间机构 | 位姿、关节变量、约束反力 | 姿态连续、约束反力有限、参考系一致 | 参考系错配会导致结果明显失真 |
| 柔性系统 | 变形量、模态响应、能量变化 | 变形量与载荷规模匹配，无无界发散 | 柔性参数或模态文件错误会放大响应 |

## 多体动画后处理要求（按需）

只有用户明确要求动画，或动画是验收合同指定证据时，才在 Sysplorer 后处理中打开多体动画。否则动画检查为 `not_required`。

检查规则：

- 对曲柄滑块、曲柄连杆、平面四杆等带环机构，必须通过动画观察闭环是否正常闭合、是否存在机构跳变、错位或异常穿越。
- 对三维多体模型，必须通过动画观察刚体姿态、关节运动、约束关系和明显干涉。
- 本节仅适用于已请求动画的任务；动画结论与验收合同要求的数值证据结合判断。未请求动画时不调用动画工具；仅请求动画时也不自动扩大数值/KPI读取范围。
- 若动画显示机构运动异常，即使关键变量曲线可读，也不能直接判定交付通过。
- 交付记录中必须写明动画是否已打开、观察对象、观察结论和仍需复查的问题。

## 结果判断纪律

- 先确认观察变量选对，再判断模型是否有误。
- 先判断结构和参数是否合理，再考虑求解器优化。
- 结果验证为 `required` 时，未通过关键变量验证前，不得把“仿真跑通”表述为“模型完成”。
- 若结果异常，必须说明异常时段、异常变量和更可能的根因方向。
- 结果变量较多时优先批量读取；对每个关键变量只取必要的初值、末值、峰值或少量时间点，避免用逐点全量输出消耗上下文。
- 验收仅要求 `check + translate + simulate` 时，三项成功且父流程要求的 Gate 6 已完成后立即结束；结果读取、曲线和动画均为 `not_required`。
