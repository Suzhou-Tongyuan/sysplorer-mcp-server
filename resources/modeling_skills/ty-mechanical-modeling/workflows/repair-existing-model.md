# 修复已有模型 / Repair Existing Model

## 默认读取集

- 必读：`references/common-errors.md`
- 按需：`references/parameter-rules.md`，仅在确认是参数问题且组件名单稳定后读取
- 按需：`references/validation-rules.md`，结构预检只读相应章节；结果部分仅在用户要求结果校核时读取
- 默认不要先读全部 reference，只围绕当前失败阶段定位问题

## 适用场景

- 已有 TY 机械模型出现 `check`、`translate`、`simulate` 或结果异常问题。
- 用户需要修复连线、参数、初值、约束或组件选择问题。

## 最短闭环

1. 已有故障由父级调试路线主导，先识别失败阶段，再读取 `references/common-errors.md` 补充机械排查项；不重跑新建流程。纯诊断先考虑 MCP 0.4 自动布局写回边界，使用授权副本或记录不能只读验证的限制。
2. 保持 TY 库边界不变，优先做最小修复，不大范围重写无关结构。
3. 结构问题先回到 `check`；翻译问题先查状态选择、初值和约束；仿真问题先查初值、约束和参数数量级。
4. 仅在确认是参数问题时，重新通过 Sysplorer 参数查询接口核对真实参数名。
5. 若错误涉及跨库连接、端口类型或 inner/outer world，先回到组件文档和端口查询，不要只改连线坐标或参数。
6. 若错误涉及方程不平衡，先列出自定义组件的变量、输入输出和方程来源，再修改源码。
7. 会话、错误分类及重试预算复用父级 shared-standards；需要时建立更小的复现模型或做静态源码检查后再继续。
8. 修复后从受影响的最早阶段复验至用户约定终点；仅结果查询/后处理修正按 `references/error-repair-playbook.md` 复用有效既有结果，只重做受影响查询/核验，不自动重新仿真。未要求的 result verify、曲线和动画为 `not_required`。图形改动完成适用 Gate 6，普通交付提供简洁证据，正式报告仅按请求生成。

## 输出重点

- 说明故障阶段、根因判断和最小修复动作。
- 说明是否做过接口/方程/自由度预检，以及预检发现。
- 说明修复后重新执行成功的阶段。
- 说明仍未闭环的问题和下一步建议。
