# 参数估计实战总结

本文档总结在 Sysplorer 中使用 `DesignOptMpe` 进行参数估计/参数标定的实操方法，重点覆盖：

- 标准工作流
- 常用 API
- 参数、变量、测量数据的配置方法
- 残差函数与算法选择
- 常见踩坑点
- 可直接复用的脚本模板

适用场景：

- 需要基于 `DesignOptMpe.py` 跑参数估计
- 需要把模型输出和测量数据做拟合
- 需要快速确认应如何设置调节参数、固定参数、变量映射、残差函数和优化算法

## 1. 基本认识

`DesignOptMpe` 是 Sysplorer 的参数估计工具箱。典型目标是：

- 选择若干模型参数作为待调参数
- 绑定测量数据文件
- 指定模型输出变量和测量列之间的映射关系
- 指定仿真时间与估计时间窗
- 选择残差函数和优化算法
- 启动估计，得到最优参数与残差

典型导入方式：

```python
import mworks.sysplorer as sysplorer
import mworks.sysplorer.DesignOptMpe as mpe
```

## 2. 标准工作流

推荐按下面顺序执行：

1. `OpenModelFile(...)` 加载模型文件
2. `InitialApp(modelName)` 初始化参数估计环境
3. `GetTunerParam()` 查看可调参数
4. `SelectTunerParam(...)` 选择待估计参数
5. `ConfigTunerParam(...)` 设置每个待估计参数的上下限和初值
6. `NewExpAttachPath(...)` 绑定测量数据文件
7. `SetEstimateExp(...)` 指定当前估计实验
8. 如果需要固定参数，执行 `SelectFixParam(...)` 和 `ConfigFixParam(...)`
9. `SetSimulateVariable(...)` 建立“模型变量 -> 测量列”映射
10. `SetSimulateOption(...)` 设置仿真时间和估计时间窗
11. `SetEstimateOption(...)` 设置残差函数和并行数
12. `SelectAlgorithm(...)` 选择优化算法
13. `ConfigPSOAlgorithm(...)` 或 `ConfigGAAlgorithm(...)` 配置算法参数
14. `StartEvaluate()` 先评估初值
15. `StartEstimate()` 启动正式估计
16. `GetEstimateResult()` / `GetEstimateParamData(...)` / `GetEstimateReport()` 读取结果
17. `CloseApp()` 收尾

说明：

- `StartEstimate()` 是阻塞接口，必须等待它结束后再读取结果。
- 如果中途提前取结果，容易误判“优化不彻底”。

## 4. 残差函数支持项

当前支持这 5 种残差函数：

- `Mean Error`
- `Mean Absolute Error`
- `Mean Percentage Error`
- `Mean Absolute Percentage Error`
- `Mean Squared Error`

经验建议：

- 想直接压低曲线点对点差值，优先试 `Mean Absolute Error`
- 想强调相对误差，使用 `Mean Absolute Percentage Error`
- 想放大大误差点影响，使用 `Mean Squared Error`

## 5. 优化算法支持项

当前可用算法：

- `Bobyqa`
- `Cobyla`
- `GA`
- `PSO`
- `Praxis`

经验建议：

- 全局搜索先用 `PSO`
- 已有较好初值后做局部精修，可再尝试 `Bobyqa` 或 `Cobyla`
- 参数较多、模型非线性明显时，`PSO` 通常更稳

## 6. 什么时候走原生 MPE，什么时候走自定义路径

### 6.1 原生 MPE

适合：

- 用户明确要用 `PSO`、`GA` 等内置算法
- 场景比较标准
- 不需要大量候选参数并行评估

### 6.2 自定义路径

适合：

- 用户要求高性能外部算法
- 需要混合优化策略
- 多边界工况较多
- 稳态工况较多，单次参数评价涉及大量仿真
- 希望由 skill 自动选择较优自定义算法

当前默认优选算法：`lshade`

## 7. 原生 MPE 标准流程

1. `OpenModelFile(...)`
2. `InitialApp(modelName)`
3. `GetTunerParam()` / `GetVariable()` / `GetMeasureVariable(expName)`
4. `SelectTunerParam(...)`
5. `ConfigTunerParam(...)`
6. 配置实验
7. `SetEstimateExp(...)`
8. 非多边界场景下，必要时再配置固定参数
9. 配置变量映射、仿真时间与估计时间
10. `SetEstimateOption(...)`
11. `SelectAlgorithm(...)`
12. `StartEvaluate()`
13. `StartEstimate()`
14. 读取结果

## 8. 自定义批量优化标准流程

1. 准备参数信息
2. 准备边界列表
3. 准备变量映射
4. 准备测量数据
5. 设置仿真时间、估计时间、稳态时间
6. 处理模型额外依赖库：先询问用户，未提供时自动推导
7. 长时间优化前先执行预检
8. 初始化批量仿真
9. 先使用参数初始值评估一次，并作为第一条迭代信息
10. 将候选参数展开到各个边界
11. 批量取回仿真结果
12. 统一计算残差
13. 迭代优化，并实时写出进度日志

依赖库处理规则：

- 用户提供模型文件后，优先确认是否有 `Modelica` 之外的依赖库
- 用户给出依赖库时，写入 `scenario.extra_libraries`
- 用户未给出或不确定时，从模型文本和 Sysplorer 安装目录中的库名自动推导并用于后续流程
- 依赖库加载早于模型检查、模型翻译、短仿真检查和批量仿真初始化
- 缺库时 `CheckModel` / `TranslateModel` 可能阻塞，因此不要把它们作为第一步缺库探测

## 9. 统一残差规则

### 9.1 支持的残差函数

支持的 5 种残差函数与经验建议见第 4 章。自定义优化默认使用 `Mean Absolute Percentage Error`。

百分比类残差的分母规则：

- 实测值非 0：分母取实测值
- 实测值为 0：分母取 `1`

### 9.2 多边界残差层级

1. 单点偏差  
   `e(b,v,k) = sim - measure`

2. 单变量残差  
   `R(b,v) = phi(e(b,v,k))`

3. 单边界残差  
   `B(b) = mean_v(R(b,v))`

4. 总残差  
   `J = sum_b sum_v abs(w(b,v) * R(b,v))`

说明：

- `B(b)` 只用于诊断
- 最终优化目标是 `J`
- 边界之间不再额外平均
- 边界优先级通过变量权重体现

### 9.3 “无边界”场景的统一处理

如果用户没有显式定义边界，也不要走单独逻辑。

统一做法：

- 自动构造 1 个虚拟边界
- 后续残差计算、批量展开、结果回组全部沿用同一套逻辑

## 10. 稳态工况规则

稳态参数估计时：

- 稳态场景应提供目标比较时间，也就是稳态时间
- 未给出时默认使用参数估计结束时间
- 如果仿真数据没有该时刻，必须插值
- 残差只需要对比该稳态时间点的数据

这条规则适用于单边界稳态，也适用于多边界稳态。

## 11. 批量仿真规则

自定义优化统一使用：

```python
import mworks.sysplorer.DesignOptExp as exp
```

核心接口：

- `exp.InitialBatchSimulate(...)`
- `exp.BatchSimulate(...)`

展开方式：

- 候选参数组数为 `N`
- 边界数为 `B`
- 实际批量仿真任务数为 `N * B`

执行顺序：

1. 为每个候选参数复制 `B` 份
2. 每份附加对应边界参数
3. 调 `BatchSimulate(...)`
4. 将返回结果按候选参数重新切块
5. 逐组计算总残差

## 12. 仿真失败规则

如果某组参数的任一必要边界仿真失败：

- 该组参数总残差直接记为 `1e300`

这样优化器会自动淘汰该参数组。

## 13. 自定义算法说明

当前 skill 内支持：

- `lshade`
- `basic-de`
- 外置算法适配器

其中：

- 未指定具体自定义算法时，默认使用 `lshade`
- `basic-de` 作为兼容基线算法保留
- 用户指定未内置算法时，先判断算法是否适合当前批量仿真残差闭环；适合则创建适配器后接入

推荐优先级：

1. `lshade`
2. `basic-de`

`lshade` 正式优化推荐配置：

- 种群规模：`20`（推荐值；未显式配置时由脚本按参数维数自动取值）
- 最大迭代次数：`100`（脚本默认值）
- 批量仿真并行数：`10`

配置解释：

- 随机种子用于保证随机搜索过程可复现，不是算法必须的固定常数
- 数值仿真容差是模型求解器的误差容限，不是 `lshade` 的收敛容差
- 求解器配置用于每次候选参数的 Sysplorer 模型仿真，不属于 `lshade` 算法本体

### 13.1 外置算法适配器标准流程

当用户提出某个未内置算法时：

1. 先调研算法机制和常用实现，优先查论文、官方文档或可信实现说明
2. 判断是否满足适配条件：
   - 输入可以表示为数值参数向量
   - 目标可以表示为越小越好的标量残差
   - 能处理有限上下界，或可以通过变换/修复处理边界
   - 能接受昂贵函数评估，不依赖海量快速调用
   - 不强依赖解析梯度、Hessian、模型方程或可微性
3. 若适合，编写本地 Python 适配器模块
4. 适配器通过统一批量评估接口评价候选参数，不直接调用 Sysplorer
5. 适配器输出与内置算法一致的 `best`、`history` 和逐步进度信息
6. 再走自定义批量优化流程

框架在调用外置适配器前会统一执行预检并完成一次参数初始值评估；适配器返回的历史记录必须保留该初始评估作为第一项。

对外说明时，只说“外置算法适配器”。内部入口名、配置字段名、回调名和实现类名只在用户明确要求生成配置或脚本时输出。

## 15. 关键踩坑点

### 15.1 名称必须以工具实际枚举结果为准

不要只看模型源码里写的名字，要以工具枚举结果为准：

- 待调参数看 `GetTunerParam()`
- 固定参数看 `GetFixParam()`
- 变量映射看 `GetVariable()`

例如在 `NewSimplerCar.SimpleCar` 里：

- 不是 `engineTorque.tau_0`
- 而是 `engineTorque1.tau_0`

又例如：

- 不是 `carbody.a`
- 也不是 `carBody.a`
- 而是 `CarBody.a`

`DesignOptMpe` 对大小写和实例名都敏感。

### 15.2 固定参数必须先选再配

固定参数的正确顺序：

```python
mpe.SelectFixParam("exp", ("gearBox.ratio",))
mpe.ConfigFixParam("exp", "gearBox.ratio", 2.34)
```

如果只配不选，通常不会生效。

### 15.3 变量映射左边是模型变量，右边是 CSV 列名

```python
mpe.SetSimulateVariable("exp", "CarBody.a", "acc")
```

含义：

- 左边 `CarBody.a` 是模型仿真结果变量
- 右边 `acc` 是测量文件中的列名

### 15.4 `StartEstimate()` 是阻塞调用

它会一直跑到估计结束。正确做法：

```python
ok = mpe.StartEstimate()
result = mpe.GetEstimateResult()
```

不要在估计未结束时提前根据中间值下结论。

### 15.5 上下限不要乱设

上下限过宽会导致：

- 收敛慢
- 结果漂移
- 局部最优和无效搜索增多

建议原则：

- 初值附近先给合理范围
- 如果一轮结果靠近边界，再考虑扩边
- 如果参数出现物理上不合理的值，要及时缩小范围

## 16. `NewSimplerCar` 实战经验

模型：

- `NewSimplerCar.SimpleCar`

典型映射：

- 模型变量：`CarBody.a`
- 测量列：`acc`

实际可调参数名称：

- `engineTorque1.tau_0`
- `gearBox.lossTable[1,2]`

固定参数示例：

- `gearBox.ratio = 2.34`

示例时间窗：

- `SimStartTime = 3.8`
- `SimEndTime = 6`
- `estimateStartTime = 3.8`
- `estimateEndTime = 6`

示例配置：

```python
mpe.SelectTunerParam(("engineTorque1.tau_0", "gearBox.lossTable[1,2]"))
mpe.ConfigTunerParam("engineTorque1.tau_0", 100, 400, 320)
mpe.ConfigTunerParam("gearBox.lossTable[1,2]", 0, 1, 1)

mpe.NewExpAttachPath("exp", r"C:\\path\\Acceleration_measurements.csv")
mpe.SetEstimateExp("exp")

mpe.SelectFixParam("exp", ("gearBox.ratio",))
mpe.ConfigFixParam("exp", "gearBox.ratio", 2.34)

mpe.SetSimulateVariable("exp", "CarBody.a", "acc")
mpe.SetSimulateOption(3.8, 6, 3.8, 6)
mpe.SetEstimateOption("Mean Absolute Percentage Error")
mpe.SelectAlgorithm("PSO")
mpe.ConfigPSOAlgorithm()
```

## 17. `Muscle` 实战经验

模型：

- `Muscle`

变量映射：

- 模型变量：`y`
- 测量列：`muscle`

建议调节参数：

- `B`
- `J`
- `K`
- `alpha`
- `beta`
- `tau`

一组常用范围：

- `B`: `0 ~ 10`，初值 `3`
- `J`: `0 ~ 3`，初值 `1`
- `K`: `0 ~ 150`，初值 `75`
- `alpha`: `0 ~ 2`，初值 `0.2`
- `beta`: `0 ~ 2`，初值 `0.1`
- `tau`: `0 ~ 1`，初值 `0.005`

示例配置：

```python
params = [
    ("B", 0, 10, 3),
    ("J", 0, 3, 1),
    ("K", 0, 150, 75),
    ("alpha", 0, 2, 0.2),
    ("beta", 0, 2, 0.1),
    ("tau", 0, 1, 0.005),
]

mpe.SelectTunerParam(tuple(p[0] for p in params))
for name, mn, mx, init in params:
    mpe.ConfigTunerParam(name, mn, mx, init)

mpe.NewExpAttachPath("muscle_exp", r"C:\\path\\muscle.csv")
mpe.SetEstimateExp("muscle_exp")
mpe.SetSimulateVariable("muscle_exp", "y", "muscle")
mpe.SetSimulateOption(0, 5, 0, 5)
mpe.SetEstimateOption("Mean Absolute Error")
mpe.SelectAlgorithm("PSO")
mpe.ConfigPSOAlgorithm()
```

## 18. 推荐优化策略

### 18.1 粗搜

先用 `PSO` 默认参数做一轮：

- 看残差能否明显下降
- 看最优参数是否逼近上下限
- 看不同参数是否有明显漂移

### 18.2 缩范围

如果一轮结果已经比较稳定：

- 以当前最优值为中心缩小参数范围
- 再跑第二轮

这通常比一开始给超大范围更有效。

### 18.3 深化搜索

如果觉得 `PSO` 跑得不够彻底，可以提高：

- `maxIterStep`
- `populationSize`
- `convergenceTime`

例如：

```python
mpe.ConfigPSOAlgorithm(
    relativeTolerance=1e-5,
    convergenceTime=10,
    maxIterStep=300,
    populationSize=60,
    parameterAdaptive=True,
    w=0.6,
    c1=1.5,
    c2=2,
)
```

### 18.4 局部精修

在 `PSO` 得到较好初值后，再试：

- `Bobyqa`
- `Cobyla`

这类局部算法常用于最后进一步压低残差。

## 19. 结果读取建议

最常用的结果读取方式：

```python
result_names = mpe.GetEstimateResult()
best_param = mpe.GetEstimateParamData(result_names[0])
report = mpe.GetEstimateReport()
result_data = mpe.GetEstimateResultData()
```

建议同时看三类信息：

- 最优参数值
- 最终残差
- 迭代报告

其中迭代报告最有价值，因为能判断：

- 是否还在持续下降
- 是否过早停住
- 是否值得再扩大迭代次数

## 20. 最小可运行模板

```python
import mworks.sysplorer as sysplorer
import mworks.sysplorer.DesignOptMpe as mpe

sysplorer.OpenModelFile(r"your_model.mo")

assert mpe.InitialApp("YourModel")

mpe.SelectTunerParam(("param1", "param2"))
mpe.ConfigTunerParam("param1", 0, 10, 1)
mpe.ConfigTunerParam("param2", 0, 5, 0.5)

mpe.NewExpAttachPath("exp", r"measure.csv")
mpe.SetEstimateExp("exp")

mpe.SetSimulateVariable("exp", "simVar", "measureVar")
mpe.SetSimulateOption(0, 10, 0, 10)

mpe.SetEstimateOption("Mean Absolute Error")
mpe.SelectAlgorithm("PSO")
mpe.ConfigPSOAlgorithm()

mpe.StartEvaluate()
print(mpe.GetEvaluateResultData())

mpe.StartEstimate()

result_names = mpe.GetEstimateResult()
print(result_names)
print(mpe.GetEstimateParamData(result_names[0]))
print(mpe.GetEstimateReport())

mpe.CloseApp()
```

## 21. 快速检查清单

正式跑估计前，建议逐条确认：

- 模型类名是否正确
- 待调参数名是否来自 `GetTunerParam()`
- 固定参数名是否来自 `GetFixParam()`
- 仿真变量名是否来自 `GetVariable()`
- CSV 列名是否与测量文件完全一致
- 时间窗是否覆盖有效测量区间
