# 新建与改模规则

本文件只补充 TA 车辆模型的新建与改模规则，不承担父级建模流程职责。

## 适用场景

- 新建整车模型。
- 新建车辆子系统模型。
- 用 TA 库细化已有模型。
- 对已有车辆模型做结构性重构。

## 建模规则

1. 先识别主目标、车型架构、目标输出和落地等级。
2. 通过 `library-selection.md` 选择主库和必要辅助库。
3. 若形成用户车辆库，先读 `package-design.md` 确定车辆业务分层；通用 Modelica package 文件规则仍按父级 [Modelica 文件规范](../../ty-sysplorer-modeling-rules/references/modelica-style-guide.md) 执行。
4. 写模型前必须先形成“建模契约”：主目标、车型架构、工况、落地等级、主库/辅助库、参考案例或参考类、顶层组件、暴露接口/总线；结果验收在范围时填写预期结果变量，否则记 `not_required`。缺少建模契约时停止写模型，先补契约。
5. 可以选取最接近的官方案例作为建模和排版的参考，有问题可以看看案例怎么做的，不允许直接将整个案例模型复制或者 `extends` 过来。
6. 禁止把完整官方整车架构、完整子系统模板或官方示例作为新交付模型的直接父类。允许的 `extends` 仅限小粒度接口、connector、record、replaceable partial 基类，或用户自有抽象，且不得隐藏本次需求要求可见的拓扑。
7. 建模困难、内部信号接线找不到或反复调试失败时，不能改用完整官方案例/架构 `extends` 作为捷径；应缩小范围、拆分子系统、保留显式组件和连接，或明确报告阻塞点。
8. 先定拓扑、接口和层级，再做组件摆放、连接和图面分区。交付模型应显式包含关键组件实例和 `connect(...)`，不能把关键拓扑藏在继承来的整车模板里。
9. `check_model`、翻译或仿真前必须做源码自检：若已有 `.mo` 文件路径，优先运行 `scripts/audit_modelica_source.py`；包内模型显式传入已获准读取的顶层包目录 `--dependency-root`，只检查目标至该根的 `package.mo`，不自动向根外追溯。否则在已授权证据范围内手动检查独立文件或顶层包的 `uses(Modelica(version = "4.0.0.TY.1"))`、无完整模板/案例直接 `extends`、关键组件与连接可见、没有未经说明的非默认参数、没有超出建模契约的库依赖。
10. 源码自检失败是停止条件，不得继续进入 `check_model`、翻译或仿真。
11. 完成首轮模型后，回到父级 `ty-sysplorer-modeling-rules` 的检查、布局、翻译、仿真和交付闭环。

## 车辆注意点

- 不要一上来把 6 个库一起接入。
- 优先保持结构边界清楚，每一层只暴露必要接口。
- 顶层及子模型图形对象的验收范围按父 Gate 6，以本次实际新建/修改为准；未触及对象不扩查，纯视觉缺陷不阻塞检查/翻译/仿真。
- 官方示例只用于参考拓扑、参数习惯、结果变量和图面风格。
- 若选择默认骨架，必须说明参考的是哪类官方案例或类，但交付模型仍应显式实例化关键组件，不得直接继承完整骨架。
- 若源码自检发现违反建模契约、Modelica 版本不对、或完整模板/案例直接 `extends`，必须停止进入仿真，先重构模型。

## 大模型与超时控制

- 对整车、多轴、多库联合、热管理多回路等大任务，先落最小可检查骨架，再逐步补子系统；每一步都保留可回退的建模契约。
- 优先使用 library card 的速查入口定位候选骨架和案例，不从顶层包无边界递归探索。
- 按父级 `../../ty-sysplorer-modeling-rules/references/shared-standards.md` 区分基础设施原样重试、同一修复假设与新证据推进；同一策略无新证据时停止，记录阻塞接口，必要时缩小到约定范围内的子系统或静态骨架。
- 对“默认参数，无异常不改”的任务，除闭合接口和初始化必需项外不要主动改参数；若必须改，记录原因和影响。
- 对多轴/六轮等非标准整车，先确认车身、轮端、制动、驱动、转向和自然滑行轮的接口数量，再写连接；不要用四轮模板直接假装六轮模型已完成。
