# 车辆图面与布局补充规则

本文件补充车辆分区、总线与接口的图面检查项，不承担车辆任务入口职责。图面触发、时序和完成状态以 `../../ty-sysplorer-modeling-rules/workflows/seven-gates-validation.md` 的 Gate 6 为准；MCP 工具、会话和错误契约以其 `references/shared-standards.md` 为准。

适用于：

- 新建模型后的图面整理
- 现有模型布局整改
- `Placement`、`Line(...)` 与连接可视化结构核查

## 车辆图面补充规则

本文件只补充 TA 车辆模型的图面分区、案例参考和源码级检查口径；图面时机和布局闭环仍服从父级 `ty-sysplorer-modeling-rules` 的 Gate 6。

- 本次新建或实际修改的系统、子系统和组件图形对象执行适用 Full Gate 6；未修改的继承对象与未触及层级不展开。只读、Documentation-only、无图形对象的纯代码或未改变图形目标的任务标记 `not_required`。
- 图面整理可与功能验证并行；图形注解语法/结构错误由检查阻断，纯视觉缺陷不阻塞检查、翻译或仿真，完整图形交付前仍须闭合适用 Gate 6。
- 关键组件必须有 `Placement`，关键连接必须有可见路径。
- 模型应先参考对应库卡片列出的官方样例入口；这些入口均指向当前 Sysplorer 安装目录下的 `Docs\VehLib\Samples\<库名>` 及其子目录。其他来源只作为备选方案。
- 若当前功能未闭环，只能写“功能未完成，但图面已完成/未完成”，不得写“图面待整理”。

## 核心目标

1. 让顶层模型和本次新建子模型在图形注解层面达到结构清晰、可维护、可交付状态。
2. 让主能量流、主信号流、主接口边界一眼可读。
3. 让图面整理独立闭环，不依赖功能是否已经完全跑通。

## 基本原则

1. 图面是交付内容，不是附属项。
2. 不依赖 Sysplorer 自动散排兜底，必须显式落到 `Placement`、`Line(...)` 和可见连线结果。
3. 图面整理与功能验证并行推进，不是功能跑通后的后置步骤。
4. 默认先确定分区方案，再落组件坐标和连线走向。
5. 默认先参照最接近的官方案例，再做当前任务的定制化布局；官方案例优先级以对应库卡片列出的 `Docs\VehLib\Samples\<库名>` 入口为准，其他来源只作备选。

## 强制完成定义

仅对父 Gate 6 判定适用的本次新建/修改图形对象，以下内容属于图面完成条件：

- 顶层模型已完成布局、可见连线和标签整理
- 本次新建或实际修改的子系统/组件图形对象已完成基本布局
- 关键组件有明确 `Placement`
- 关键连接有明确 `Line(...)` 路径，而不是只有无图形注解的 `connect(...)`

如果功能尚未闭环，应表述为“功能未完成，但图面已完成/未完成”；不得写成“图面后补”。

## 默认排版原则

- 子系统优先按真实物理结构、主能量流和主信号流组织
- 同类组件成组摆放，相关组件相邻，减少长距离交叉连线
- 读图时应能一眼看出主框架、细化子系统和关键耦合点
- 热管理相关任务优先按回路和换热关系排布，使空气、冷却液、制冷剂路径各自清晰
- 默认骨架确定后，仍要继续参照最接近的官方架构或案例优化留白、总线主干和关键连线路径

## 执行顺序

1. 按主目标确定图面骨架。
2. 参考最接近的官方案例，提炼分区、主连线路径、总线走向和留白关系。
   默认先查看对应库卡片列出的官方样例入口；这些入口均指向当前 Sysplorer 安装目录下的 `Docs\VehLib\Samples\<库名>` 及其子目录。其他来源只作为备选；若与库卡片入口冲突，以库卡片入口为准。
3. 先摆主体，再摆辅助模块，再收束连线。
4. 对外连接只通过真实接口。
5. 直接检查源码中的 `Placement`、`Line(...)`、组件分区和接口方向；发现缺失或明显冲突时继续调整注解。

## 源码级检查

结构化检查以模型源码、组件层级、图形注解、连接器端点及布局工具诊断为共同基础：

- 本轮适用的顶层、子系统与组件图形对象是否包含关键组件的 `Placement`
- 关键 `connect(...)` 是否带有对应 `Line(...)` 注解
- 组件坐标是否体现主框架、关键子系统和接口边界
- 主能量流、主信号流和主物理连接是否按区域组织
- 子模型边界接口位置是否服务于外层连接方向

若结构化证据不足，应将对应检查项写为“未验证”，不得凭工具执行成功推断图面通过。图片按用户要求或可用且有帮助的能力选用：先 `get_api_document("ExportDiagram")`，再按官方参数用 `call_code(mode="run_sysplorer_api", payload={...})` 导出，不使用已退役 manager 导图动作。未查看图片不得声称目视确认；用户明确要求图片而能力不可用时，单列图片交付未完成，不静默忽略要求。

MCP 0.4 的 check/translate/simulate 可能自动布局写回并重载，即使未传 `reload_mo_path` 也可能发生。只读评审不能直接承诺 check 无写入；遵守父规则授权范围。实际写回触发对应图形对象 Gate 6；分别记录 `disk_changed`、`official_route`、`persisted`、`layout_writeback_ok`、`session_persist_ok`，不把布局执行、会话布线、落盘或模型检查通过等同于图面验收通过。

## 子模型图面要求

当父 Gate 6 适用于本次新建或实际修改的子模型图形对象时，必须满足：

- 子模型内部关键组件按物理功能成组摆放
- 子模型内部关键连接有可见连线
- 子模型边界接口位置服务于外层连线的自然走向
- 不把“子模型只是中间层”当作不整理图面的理由

## 接口与外层连接规则

1. 子模型对外连接必须通过真实边界接口暴露。
2. 外层优先使用 `connect(...)` 连接真实接口，不直接跨层改写内层变量。
3. 不允许为了让图“看起来连上了”而手工补假 `Line(...)`。
4. 外层连线发红时，优先检查接口设计和接口类型，而不是继续微调连线路径。
5. 信号接口优先用 `input` / `output` 或明确信号连接器；物理端口要用对应领域连接器。

## 各领域默认骨架

- `TADynamics` 高度集成：
  驾驶员、驱动系统、整车集成模型、制动系统从左到右，控制模块放右上，道路放右下
- `TADynamics` 分散布局：
  转向在上、车身在下，四轮围绕车身按真实位置排布
- `TAEconomy`：
  按中轴结构排布，驾驶员放最左
- `TABattery`：
  保持 cell -> module -> pack 层级
- `TAElectronic`：
  公共供电点放下方，负载向其汇接
- 热管理相关：
  热路径、主信号链和附件路径分开布置

## 快速检查清单

- 主框架和细化子系统分工是否一眼可见
- 主动力链、制动链、热路径和控制链是否分层
- 四轮、悬架、车身是否按真实车辆关系排布
- 总线是否遮挡主体结构
- 子模型内部是否也完成了基本整理
- 用户可见文字是否默认使用中文
