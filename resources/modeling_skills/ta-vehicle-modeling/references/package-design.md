# TA 车辆用户库业务分层

本文件只补充 TA 车辆用户模型库的**业务分层**。通用 Modelica 目录结构、`package.mo`、`package.order`、`uses(...)`、文件命名和 `src/<LibraryName>/` 组织规则，以 [父级 Modelica 文件规范](../../ty-sysplorer-modeling-rules/references/modelica-style-guide.md) 为准；本文件不得替代或放宽父级规则。

## 何时读取

仅在任务需要形成或整理用户车辆模型库时读取，例如：

- 新建一套车辆模型库。
- 把整车装配、子系统、测试模型拆分到合适层级。
- 将临时模型整理为可复用交付结构。
- 判断某个子系统应该留在整车装配内，还是升格为独立类。

如果只是搭一个单模型、修一个已有模型、查样例或核验结果，通常不需要读取本文件。

## 设计目标

- 让整车装配、可复用子系统、测试模型和公共适配层职责清楚。
- 让车辆模型库便于后续扩展、复用、单独检查和单独仿真。
- 避免把所有车辆结构堆在一个顶层整车模型里。
- 避免把临时调试结构误放进正式交付层。

## 推荐业务层

按任务需要选择下列业务子包，不要求全部创建：

| 业务层 | 适用内容 |
|---|---|
| `VehicleAssemblies` 或 `Examples` | 整车装配主入口、整车级示例和交付入口。 |
| `DriveSystems` | 电机、发动机、传动、驱动桥、动力链子系统。 |
| `SuspensionAndChassisSystems` | 悬架、车身、转向、制动、轮胎、道路和底盘动力学组合。 |
| `ThermalManagementSystems` | 热管理回路、HVAC、水冷、制冷剂回路、热泵系统。 |
| `BatterySystems` | 电芯、模组、电池包、BMS、电热耦合和电池热管理子系统。 |
| `ElectricalSystems` | 低压母线、DCDC、附件负载、车身电器和电器域组合。 |
| `ControlModules` | 控制器、策略模块、信号适配和联合仿真控制边界。 |
| `BusModels` | 车辆总线、信号连接器、适配器和跨库接口结构。 |
| `Utilities` | 车辆领域通用函数、记录类型、适配模型和非业务主链工具。 |
| `Tests` | 可复用子系统测试、最小验证模型和回归检查模型。 |

命名可根据项目习惯调整，但职责边界应保持清楚。

## 整车装配与子系统边界

- 整车装配模型只负责实例化、连接和配置已有子系统。
- 可复用、需要单独测试、需要单独说明或会被多个整车入口复用的结构，应升格为独立子系统类。
- 子系统对外连接必须通过真实接口、总线或连接器暴露，不跨层引用内部变量。
- 车辆总线、控制边界和跨库适配器优先放在可复用层，不散落在多个整车装配模型里。
- 官方样例只能作为结构参考；若要交付用户库，应形成用户项目自己的类名、边界和说明。

## 子系统内部建议

对较大的业务子包，可按需拆分：

```text
<BusinessPackage>
  Components
  Subsystems
  Tests
```

- `Components`：不可再拆或复用粒度较小的部件封装。
- `Subsystems`：由多个部件组成、对外暴露清晰接口的车辆子系统。
- `Tests`：子系统级最小验证模型。

只有存在共用基类、partial 模型、适配器或公共类型时，才额外建立 `Basics`、`Interfaces` 或 `Utilities` 等层级；不要为了形式完整而空建目录。

## 禁止结构

- 在一个整车模型内部声明大量局部 `model`，导致无法复用和单独检查。
- 把可复用子系统藏在整车装配模型内部。
- 顶层整车模型同时承担装配、所有子系统定义、测试和调试副本归档。
- 把调试副本、失败试验和临时替代件放入正式交付层。
- 为了匹配某个示例目录，强行创建与当前任务无关的业务层。

## 最小可交付结构

新建用户车辆库时，最小结构通常应能回答：

1. 哪个类是整车或系统主入口。
2. 哪些子系统是可复用独立类。
3. 哪些接口、总线或适配器承担跨库连接。
4. 哪些测试模型用于验证关键子系统。
5. 哪些内容是正式交付，哪些只是调试或参考。

若这些问题无法回答，先不要扩展更多子包；应先收敛主入口和子系统边界。
