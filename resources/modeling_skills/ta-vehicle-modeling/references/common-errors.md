# 常见错误与排查顺序

本文件用于 TA 车辆整车与子系统模型的高频故障排查。  
先用 `error-repair-playbook.md` 判断故障类别和最短修复链；遇到下列具体现象时，再用本文件查优先排查顺序。

| 现象 | 可能原因 | 优先排查顺序 | 修复建议 |
|---|---|---|---|
| 整车不运动 | 驾驶员/循环工况未真正驱动、动力源未接入、制动未释放、传动链或车身/道路路径未闭合 | 驾驶员/工况 -> 动力源 -> 传动/车桥 -> 制动 -> 车身/道路 | 先闭合最小纵向动力链，再检查控制策略和高级附件 |
| 车速无法跟随目标车速 | 驾驶员参数不合适、目标循环未接入、驱动功率不足、制动或阻力异常 | 目标车速 -> 驾驶员输出 -> 驱动功率 -> 制动状态 -> 质量/滚阻/风阻 | 先确认目标车速与实际车速变量，再调整驾驶员、驱动源和阻力参数 |
| 经济性、能耗或续航明显不合理 | 整备质量、滚阻、风阻、附件负载、SOC 初值或效率图不合理 | 质量 -> 滚阻/风阻 -> 循环工况 -> SOC -> 附件负载 -> 电机/发动机效率 | 使用 `TAEconomy` 样例参数做量级对比，不把未核验曲线写成结论 |
| SOC 不变、突变或超界 | 电池包未接入功率链、初始 SOC/容量错误、串并联数或适配器参数不一致 | 电池功率 -> 电流/电压 -> 初始 SOC/容量 -> 串并联参数 -> 总线映射 | 同时核对 `TABattery` 参数和整车功率流，不只改结果变量名 |
| 动力学模型无操稳/平顺响应 | 道路、驾驶员、转向、制动、车身、悬架或轮胎接口未闭合 | 道路/工况 -> 驾驶员 -> 转向/制动 -> 车身 -> 悬架 -> 轮胎 | 先让最小车身-悬架-轮胎-道路链路闭合，再加入驱动细化 |
| `ChassisBase`/`ChassisBase2` 开环滑行翻译缺方程 | 只给 `driverBus` 踏板/方向盘零输入，未给制动/驱动扭矩总线字段赋零；翻译错误可能沿车轮、悬架或多体力矩链路展开 | 外部 `signalBus` -> `brakeBus.brakeBus[i].tau_brake` -> `powertrainBus.emotorBus[i].tau_drive` -> 转向 `SWAngle/SWRelease` -> 道路 `flatRoad` | 对 4 个车轮分别用可视化 `Constant(k=0)` 连接 `tau_brake` 和 `tau_drive`；踏板为 0 不能替代轮端扭矩总线赋值；不要因此改成简化车模或乱接物理轮端扭矩源 |
| 车辆方向、转向响应或位移方向反了 | 坐标约定、转向符号、轮胎力方向、驱动/制动力矩方向或左右/前后编号错误 | 坐标系 -> 轮位编号 -> 转向符号 -> 轮胎力方向 -> 力矩作用点 | 修正编号和符号后重新核验横摆角速度、侧偏、轮胎力和车身姿态 |
| 动力学仿真发散或步长极小 | 轮胎/悬架参数过硬、初始速度不一致、道路输入突变、约束或接触过刚 | 初始车速 -> 道路输入 -> 轮胎参数 -> 悬架刚度/阻尼 -> 约束状态 | 先检查参数量级和初值，再考虑求解器设置 |
| 热管理温度没有变化 | 热源/热汇缺失、泵/风机/压缩机未驱动、回路未闭合、温度变量路径错误 | 热源 -> 热汇 -> 泵/风机/压缩机命令 -> 回路闭合 -> 温度变量 | 先确认热回路真实闭合和执行器命令，再读取目标温度变量 |
| 热回路温度、压力或流量异常爆炸 | 回路堵塞、边界缺失、阀状态错误、泵方向错误、换热器两侧接反 | 边界 -> 阀状态 -> 泵方向 -> 换热器连接 -> 流量/压降参数 | 先恢复主回路泄放和边界，再调控制参数 |
| 电池热管理没有效果 | 电池热接口未启用、冷却边界未接入、热管理主骨架选错、温度变量读错 | 电池热接口 -> 冷却边界 -> `TABattery`/`TAThermalSystem` 边界 -> 温度变量 | 判断是电池内部细化还是整车热管理，再补正确辅助库 |
| 发动机没有预期扭矩 | 转速边界、节气门、燃油、点火、进排气边界或控制器接口缺失 | 转速边界 -> 节气门/燃油/点火 -> 进排气 -> 控制器接口 -> 负载 | 先闭合发动机本体边界，再接整车动力链 |
| 发动机进排气或增压相关翻译失败 | 介质/边界不兼容、增压器连接错误、重声明或接口选择不一致 | 介质/边界 -> 增压器路径 -> 供油/排气 -> 重声明 -> 整车接口 | 不用整车外层信号强行绕过发动机内部接口 |
| 电池包、模组或电芯方程不匹配 | 串并联数、适配器参数、`iBattery` 编号或总线映射不一致 | 串并联数 -> 适配器参数 -> `iBattery` -> 总线映射 -> 热接口 | 成组参数必须一起改，不只改其中一个数量参数 |
| 低压电器或 DCDC 不工作 | 低压母线未闭合、电源/参考缺失、负载使能信号缺失、DCDC 参数不合理 | 低压母线 -> 电源/参考 -> DCDC -> 负载使能 -> 负载功率 | 先闭合低压供电链，再检查附件控制策略 |
| 热管理附件功率异常 | 负载时序错误、附件接在错误电器域、热执行器电气版本不匹配 | 负载时序 -> 功能域 -> 电气版本 -> 热回路接口 -> 功率变量 | 区分附件电功率归 `TAElectronic`，热回路归 `TAThermalSystem` |
| 总线字段缺失或信号重复驱动 | 总线定义不一致、多个控制器并行写同一字段、适配器重复或编号错位 | 总线定义 -> 字段来源 -> 控制器数量 -> 适配器 -> 编号 | 明确每个信号唯一归属，删除重复驱动或补适配器 |
| `CheckModel` 方程数不匹配 | 接口缺失、成组部件数量不一致、总线字段未接齐、临时占位破坏结构 | 最早报错类 -> 接口 -> 数量/编号 -> 总线 -> 临时占位 | 不要先调求解器；先修结构和接口 |
| `TranslateModel` 失败 | 参数非法、重声明冲突、连接器类型不兼容、库版本或依赖未加载 | 参数 -> 重声明 -> 连接器类型 -> 主库/辅助库 -> 依赖 | 只修当前最小阻塞组合，避免同时替换多个子系统 |
| `SimulateModel` 失败或结果 NaN | 初值不合理、控制输入突变、刚性过强、边界缺失、状态选择问题 | 初值 -> 控制输入 -> 边界 -> 刚性来源 -> 状态变量 | 先让最小工况短时仿真通过，再扩展完整工况 |
| 结果变量找不到 | 变量路径猜错、层级变化、样例变量名与当前模型不同、结果文件未打开 | 结果文件 -> 变量列表 -> 组件层级 -> 端口/结果信息 -> 目标变量 | 先列实际变量并确认语义，不猜嵌套路径 |
| 图面缺少关键总成注解 | 缺 `Placement`、子系统未落图、复制样例布局后关键组件坐标冲突 | `Placement` -> 子系统可见性 -> 分区 -> 坐标范围 | 不把模型树存在当作图面完成，补齐并检查源码图形注解 |
| 图面只有总成没有关键连接注解 | 缺 `Line` 注解、总线路径未组织或连线坐标重叠 | `Line` -> 总线路径 -> 关键连接注解 | 补关键连接路径，使主能量流、信号流和边界接口在源码布局中清晰 |
| 官方样例被误当成交付模型 | 只改名复制样例、未形成用户边界、参数/布局注解/结果未按任务核对 | 用户目标 -> 样例用途 -> 类名/边界 -> 参数 -> 布局注解/结果 | 样例只作结构和参数参考；交付前形成用户项目自己的模型入口 |

## 总体排查纪律

1. 先排查会导致完全失败的最短链路，再做样式优化或参数微调。
2. 先确认主库和车辆架构，再查具体组件。
3. 先修真实接口、总线和拓扑，不用临时信号长期绕过物理链。
4. 成组车辆部件必须同时核对数量、编号、总线索引和图面位置。
5. 图面异常优先检查源码中的 `Placement`、`Line` 和子系统分区。
6. 任何结果结论都必须先确认变量存在、数值可读、语义匹配。
7. 修复后回到父级失败 gate 复验；若修改了拓扑、参数或图面语义，重新执行受影响的检查链。
